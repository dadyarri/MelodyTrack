# Новый бэкенд MelodyTrack

Изолированный пустой каркас новой версии. Требования и архитектура находятся в [спецификации](../specification/README.md).

Solution: [MelodyTrack.Rewrite.slnx](MelodyTrack.Rewrite.slnx). Используется .NET SDK 10.0.402 с переходом на последующие исправления этой feature band, целевая платформа — `net10.0`.

| Проект | Язык | Назначение |
| --- | --- | --- |
| `src/MelodyTrack.Rewrite.Domain` | F# | Предметные модели и правила |
| `src/MelodyTrack.Rewrite.Application` | F# | Прикладные операции и порты |
| `src/MelodyTrack.Rewrite.Persistence` | F# | Работа с БД и реализация портов |
| `src/MelodyTrack.Rewrite.Api` | C# | Web API и host |
| `src/MelodyTrack.Rewrite.Init` | F# | Будущая инициализация БД |

Ссылки проектов соответствуют согласованному каркасу: `Application → Domain`, `Persistence → Application/Domain`, `Api → Application/Persistence`, `Init → Persistence`.

Проекты и сборки имеют префикс `MelodyTrack.Rewrite`, поэтому не совпадают со сборками исходной версии, включая `MelodyTrack.Init`. В корневую `MelodyTrack.slnx` они не включены. Собственные `Directory.Build.props`, `Directory.Packages.props` и `global.json` отделяют настройки новой версии от старой; корневой `.gitignore` применяется и к этому каталогу.

`Api` запускает пустой host без маршрутов. `Init` загружает конфигурацию и SQL-файлы из каталога `Migrations` рядом с приложением, проверяет их формат и вычисляет контрольные суммы. На выделенном соединении PostgreSQL он проверяет подключение, получает блокировку от параллельного Init и создаёт таблицу `public.schema_migrations`, если её ещё нет. Затем сверяет имена и контрольные суммы применённых миграций, отклоняет пропавшие файлы и новые миграции с номером ниже применённых, определяет оставшиеся миграции. SQL-файлы пока не выполняются. Миграции копируются в выходной каталог сборки и публикацию; рефлексия для их загрузки не используется. Пока SQL-миграций нет, загрузка возвращает пустой список. Коды завершения: 0 — история проверена, 1 — ошибка, включая занятость блокировки, 130 — отмена. Профиль запуска API использует `http://localhost:5280`; старая версия сохраняет свой порт 5000. Предметная схема БД, выполнение миграций, авторизация, Quartz, SqlHydra и frontend ещё не реализованы. Формат файлов описан в [каталоге миграций](src/MelodyTrack.Rewrite.Init/Migrations/README.md).

Версии зависимостей управляются локальным CPM. Persistence использует Npgsql, Init — Microsoft.Extensions.Hosting; проекты F# явно ссылаются на FSharp.Core. Остальные зависимости добавляются по мере реализации.

## Базовые настройки

- `.editorconfig`: независимые правила новой версии — UTF-8, LF, четыре пробела для C#/F#, два для JSON/XML и файлов проектов.
- `.gitattributes`: нормализация текстовых файлов и LF для исходников и конфигурации.
- `.gitignore`: локальные `.env` и файлы настроек; общие исключения сборки и IDE наследуются из корня репозитория.
- `nuget.config`: единственный источник пакетов — nuget.org; версии остаются в `Directory.Packages.props`.
- API и Init имеют собственные `appsettings.json`, `appsettings.Development.json` и профили запуска Development. Библиотеки получают настройки от запускающего приложения.

В обоих приложениях предусмотрен ключ `ConnectionStrings:Database` с пустым значением. Реальную строку подключения нужно передавать через переменную окружения `ConnectionStrings__Database`; секреты в отслеживаемые файлы не добавляются. `.env` и `appsettings.Local.json` автоматически не загружаются — исключение из Git само по себе не подключает конфигурационный провайдер.

API использует стандартный `WebApplication.CreateBuilder`, Init — Generic Host. Init читает appsettings из каталога приложения, куда JSON-файлы копируются при сборке и публикации; переменные окружения и аргументы командной строки могут переопределять значения. Профиль Init устанавливает `DOTNET_ENVIRONMENT=Development`. При ошибке подключения выводится тип ошибки без её сообщения и подробностей, которые могут содержать параметры подключения.

По запросу проверки копирования выполнена публикация Init в Debug с restore и сборкой его зависимостей. Временный SQL-файл, README миграций и оба appsettings проверены побайтовым сравнением в выходных каталогах сборки и публикации; временный SQL затем удалён. Последующее добавление блокировки и таблицы истории ещё не проверялось сборкой или запуском. Приложение и SQL не запускались, тесты не выполнялись. Остальные проверки требуют отдельного разрешения по корневому `AGENTS.md`. По D-391 бэкенд реализует ассистент небольшими порциями, останавливаясь после каждого шага для ручного ревью пользователем.
