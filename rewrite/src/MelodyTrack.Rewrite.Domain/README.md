# Домен расписания

Пакет реализует модели и чистые переходы подтверждённого блока расписания D-395 на C# 15/.NET 11 RC2. БД, HTTP, планировщик и текущее время не входят в модели; время операции передаётся явно. Идентификаторы объявлены через StronglyTypedId. Фабрики возвращают `CSharpFunctionalExtensions.Result<T, ErrorList>`; независимые ошибки накапливаются в непустом неизменяемом списке типизированных причин с привязкой к полям. Конфликт и пропуск используют пару «серия + исходный порядковый номер» без общей таблицы вхождений.

| Файл | Модели и поведение |
| --- | --- |
| `Time.cs` | UTC-интервалы, пересечение и покрытие, календарная дата/месяц Europe/Moscow |
| `Scheduling.cs` | Длительность, целый час, недельный план, условия окончания, стабильная нумерация, пошаговый расчёт кандидатов, необратимое завершение серии |
| `Catalogues.cs` | Сотрудники, помещения, услуги, периоды цен; независимость блокировки, участия и архива; проверки зависимостей при архивировании |
| `Clients.cs` | ФИО, источник, клиентский профиль, виды контактов, международные телефоны, email и ссылки; один основной контакт каждого вида, явный выбор замены основного |
| `Absences.cs` | Отпуска, заявки на создание/изменение отпуска, решения и клиентский комментарий; интервалы закрытия школы |

## Временные значения

Конкретные моменты нормализуются в UTC. Недельные часы и даты окончания серии относятся к Europe/Moscow. Интервалы проверяются как `[начало, конец)`: соприкасающиеся встречи не пересекаются, скрытых буферов нет. Окончание занятия вычисляется из начала и сохранённой длительности. Рабочий интервал может переходить через полночь; равные границы не обозначают полный день.

`Series.NextCandidate` выполняет один шаг без I/O: возвращает рассчитанную дату и новое положение курсора. Счётчик учитываемых встреч передаётся явно; пропуск или конфликт не расходует лимит. Это ещё не фоновая материализация: Application должен ограничить бессрочную серию согласованным окном 12 месяцев, сохранять курсор вместе с результатом и обеспечивать повторяемость операции.

## Границы с Application и Persistence

Проверки использования справочников, занятые интервалы и оставшиеся препятствия передаются актуальными срезами данных. Application повторяет их внутри согласованной транзакции и сохраняет изменение вместе с аудитом, финансовыми фактами и задачами/уведомлениями. Изменение статуса в чистой модели само не выполняет денежную операцию, не отзывает доступ и не отправляет уведомление.

В частности, архив клиента требует отзыва доступа, архив помещения — снятия помещения с будущего расписания, изменение графика — согласованных переносов. Модели не выполняют эти внешние действия самостоятельно. Удаление/сокращение отпуска не восстанавливает встречи автоматически. Повторный разбор конфликта и отсутствие препятствия не являются подтверждением создания занятия.

## Не подменяем открытые правила

- Занятость по состояниям проведённых, сгоревших и отменённых встреч ещё не выбрана. `AvailabilitySnapshot.BusySlots` содержит явно выбранные вызывающей операцией занятые интервалы; автоматической фильтрации по состоянию нет.
- Окончательный одобряющий отпусков остаётся вопросом заказчику. Модель заявки не выдаёт это право какой-либо роли; проверка доступа относится к прикладной операции.
- Для восстановления с компенсацией реализован обычный подтверждённый случай: запланированная неизменённая встреча хвоста с сохранённой ссылкой на отменённую встречу. Проведённый, сгоревший или индивидуально изменённый хвост возвращает `ReplacementRequiresReview`, а не выбирается автоматически.
- Источники оплаты, правила абонементов, финансовые операции, курсы, задачи и вход не входят в этот пакет расписания. Ограничения поиска дат для конечной серии, частота продления окна и сложная история восстановления остаются отдельными решениями.
- Контакты проверяются по базовому формату, без нормализации страны/оператора, схем конкретных соцсетей или сравнения дублей между клиентами. Разрешённые схемы ссылок и канонизация ещё проектируются; автоматическая публикация/выполнение ссылок не предусматривается.

## Тесты

`tests/MelodyTrack.Rewrite.Domain.Tests` содержит независимые модульные проверки по моделям: временные границы, UTC и московский месяц, нумерация/завершение серии, индивидуальные изменения, ограничения результата, причины отмен, компенсации, справочники и контакты, согласование графика и явный разбор конфликтов. Используются фиксированные даты и идентификаторы, БД/Docker не нужны. Сценарии прежних 166 тестов перенесены на C#. Добавлены проверки накопления ошибок, StronglyTypedId и защиты от пустых идентификаторов. 29.10.2026 пользователь подтвердил успешный прогон тестов; ассистент перед созданием коммитов повторно их не запускал.
