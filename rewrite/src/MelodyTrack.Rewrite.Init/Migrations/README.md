# Миграции SQL и C#

Предметные миграции должны обеспечивать обновление с предыдущей версии с сохранением данных и истории; обратная совместимость схемы не требуется. Создание новой пустой схемы не заменяет перенос. Требования и состояние локальной неизменяемой фикстуры описаны в [плане переноса](../../../docs/data-migration.md). Миграции никогда не выполняются на исходной локальной `melodytrack`: для тестов используются отдельные копии.

Файлы лежат непосредственно в этом каталоге: `0001_CreateClients.sql`, например следующий шаг может называться `0002_UpdateClients.cs`. Имя содержит четыре цифры от `0001`, подчёркивание, PascalCase латинскими буквами и цифрами, `.sql` или `.cs`. Номера общие и уникальные; пропуски допустимы. Новые миграции добавляются после последней применённой.

`0001_CreateClients.sql` создаёт источники, виды контактов, клиентов и их контакты с ограничениями целостности. `0002_CreateImportMappings.sql` создаёт служебные соответствия ID и исходных контактных полей. Обе миграции применяются и проверяются тестами на PostgreSQL 17. Поля `protected_*` записываются импортёром после защиты. Восстановление моделей, транзакционные требования и граница готовности описаны в [хранении клиентов](../../../docs/client-storage.md).

Обычный Init применяет только схему. Явный `--Import:Clients true` дополнительно читает `OldDatabase` в read-only режиме и переносит первый пакет в отдельную цель. Для импорта нужны исходные и целевые ключи; предупреждения дают код выхода 2. Повторяемость, пообъектная сверка и результат проверки локального источника описаны в [импорте клиентов](../../../docs/client-import.md).

`0001_CreateClients.sql` также создаёт нативный тип `public.contact_format` (`phone`, `email`, `link`). Отображение C# enum на PostgreSQL регистрируется в Persistence после создания схемы; Init на пустой базе работает без такого отображения. Столбец даты рождения клиента называется `birthdate`.

## Генерация

Перед компиляцией `build/Migrations.targets` вызывает C#-задачу MSBuild из `build/MigrationGeneration.cs` через RoslynCodeTaskFactory. Задача проверяет имена, UTF-8, непустое содержимое и номера, вычисляет SHA-256 исходных байтов и создаёт `obj/<configuration>/<framework>/GeneratedMigrations.cs` с единым упорядоченным массивом.

SQL включается в код как строковый литерал с обёрткой `SqlMigration.RunAsync`; C# представлен прямыми ссылками на обработчики. Файлы C# включаются стандартными правилами SDK, отдельный список исходников и порядок компиляции не нужны. Реестр объявлен в `Compile` и виден в IDE как `Generated/GeneratedMigrations.cs`. Генерация включается через `EnableMigrationGeneration=true`, каталог и namespace задаются свойствами `MigrationDirectory` и `MigrationNamespace`.

Сгенерированный файл не коммитится. Добавление и удаление миграций учитывается при каждой сборке; неизменившийся результат не перезаписывается. Ошибки источников останавливают сборку. Init использует готовый массив, не ищет файлы во время запуска, не использует рефлексию и не исполняет скрипты. После первой сборки чистого checkout IDE получает сгенерированный файл.

Исходники SQL/C# и README копируются в выходной каталог и публикацию для просмотра. Исполняемый код и checksum берутся из сборки: редактирование скопированного файла не меняет поведение Init, требуется пересборка.

## C#-миграции

Для файла `0002_UpdateClients.cs` используется обработчик с именем из файла:

```csharp
using MelodyTrack.Rewrite.Init;

namespace MelodyTrack.Rewrite.Init.Migrations;

internal static class UpdateClients
{
    internal static async Task RunAsync(MigrationContext context)
    {
        context.CancellationToken.ThrowIfCancellationRequested();
        await SqlMigration.RunAsync("UPDATE ...", context);
    }
}
```

Контекст содержит `Connection`, `Transaction`, `CancellationToken` и `Logger`. Обработчик возвращает `Task`; ручная регистрация не нужна. Можно обращаться к внешним функциям и типизированным моделям. Анализ и запрет зависимостей не выполняются по принятому решению D-394.

Checksum покрывает только исходные байты файла миграции, включая BOM и окончания строк. Изменение внешней функции или библиотеки может поменять поведение C#-миграции без изменения checksum — этот риск сохраняется. Выпущенные миграции не изменяются и не переименовываются; исправление оформляется новым шагом.

## Выполнение

Init использует сессионную advisory-блокировку PostgreSQL на выделенном соединении без pooling и multiplexing. Ключ блокировки сохраняется между версиями Init. Конкурирующий Init завершается с кодом 1. Закрытие соединения освобождает блокировку при успехе, ошибке и отмене.

До блокировки и создания истории runner отклоняет базу с `public.__EFMigrationsHistory`: выбран перенос в отдельную целевую БД, запуск нового Init на старой установке не поддерживается. Под блокировкой создаётся `public.schema_migrations`. История хранит номер, имя, checksum и время применения (`timestamptz`). Удаление, переименование или изменение применённой миграции, а также добавление миграции задним числом считаются ошибкой.

Для каждого ожидающего шага runner открывает транзакцию, вызывает `RunAsync`, записывает историю и делает commit. Ошибка прекращает обработку и откатывает незавершённый шаг; предыдущие успешные миграции сохраняются. После обрыва связи при commit следующий запуск определяет результат по истории, атомарной с изменениями миграции.

Подключением и транзакцией владеет runner. Обработчики не закрывают их и не выполняют собственные BEGIN/COMMIT/ROLLBACK. Нетранзакционные операции PostgreSQL пока не поддерживаются. Отмена передаётся явно; внешние эффекты не откатываются транзакцией БД.

При ошибке в лог попадают имя миграции и SQLSTATE PostgreSQL либо тип исключения. SQL, значения данных и полный объект исключения не логируются; исходное исключение сохраняется для отладчика. Отмена обрабатывается отдельно с кодом 130.
