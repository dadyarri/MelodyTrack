# Миграции SQL и F#

Файлы лежат непосредственно в этом каталоге: `0001_CreateClients.sql`, `0002_UpdateClients.fs`. Формат имени — четыре цифры от `0001`, подчёркивание, имя PascalCase латинскими буквами и цифрами, `.sql` или `.fs`. Номера общие для обоих видов и уникальны; пропуски допустимы, новые миграции добавляются после последней применённой.

## Генерация

Перед компиляцией MSBuild запускает `build/GenerateMigrations.fsx` из SDK F#. Генератор проверяет имена, UTF-8, непустое содержимое и номера, вычисляет SHA-256 исходных байтов и создаёт `obj/<configuration>/<framework>/GeneratedMigrations.fs` с общим упорядоченным массивом. SQL включается в код через функции-обёртки; F# представлен прямыми ссылками на обработчики. Исходники F# автоматически включаются в компиляцию по номеру, до сгенерированного реестра.

Сгенерированные файлы не коммитятся. Генерация учитывает добавление и удаление файлов при каждой сборке; неизменившиеся выходные файлы не перезаписываются. Ошибки формата останавливают сборку. Init использует готовый массив и не ищет файлы во время запуска, не использует рефлексию и не исполняет скрипты.

Реестр и список исходников F# объявляются в `Compile` уже при загрузке проекта, чтобы IDE видела их после генерации. `Directory.Build.targets` подключает `Migrations.targets` для проектов с `EnableMigrationGeneration=true`, когда SDK уже определил `IntermediateOutputPath`. В `.fsproj` сохраняется стандартное объявление `Project Sdk="Microsoft.NET.Sdk"`. После первой сборки чистого checkout или изменения состава миграций может потребоваться перезагрузка проекта в IDE; при самой сборке список исходников обновляется автоматически.

F#-миграции, реестр и использующие его файлы (`Program.fs`, интеграционные тесты) имеют `CompileOrder="CompileAfter"` в этом порядке. Это сохраняет порядок и для компилятора, и для модели проекта Rider; `CompileLast` для `Program.fs` не используется. Реестр отображается в проекте как `Generated/GeneratedMigrations.fs`, физически оставаясь в `obj`.

Исходные `.sql` и `.fs` также копируются в выходной каталог и публикацию для просмотра. Исполняемая версия и checksum берутся из сборки: редактирование скопированного файла не изменяет поведение Init, требуется пересборка.

## F#-миграции

Для файла `0002_UpdateClients.fs` используется модуль:

```fsharp
module MelodyTrack.Rewrite.Init.Migrations.UpdateClients

open MelodyTrack.Rewrite.Init

let run (context: MigrationContext) =
    task {
        context.CancellationToken.ThrowIfCancellationRequested()
        // Работа с context.Connection и context.Transaction.
        return ()
    }
```

Контекст содержит `Connection`, текущую `Transaction`, `CancellationToken` и `Logger`. Дополнительные зависимости можно добавлять именованными полями по мере необходимости. Ручная регистрация не требуется. Внешние функции, прикладные модули и сгенерированные типы разрешены; анализ и запрет зависимостей не выполняются по принятому решению D-394.

Checksum покрывает только байты файла миграции, включая BOM и окончания строк. Изменение внешней функции или библиотеки может изменить поведение F#-миграции без изменения checksum — этот риск принят пользователем. Уже выпущенные файлы миграций сохраняются; исправления добавляются новыми версиями.

## Выполнение

Init получает сессионную advisory-блокировку PostgreSQL на выделенном соединении без pooling и multiplexing. Конкурирующий Init завершается с кодом 1. Закрытие соединения освобождает блокировку при успехе, ошибке и отмене.

Под блокировкой создаётся `public.schema_migrations`, если её ещё нет. История хранит номер, имя, checksum и время применения (`timestamptz`). Удаление, переименование или изменение применённой миграции и добавление миграции задним числом считаются ошибкой.

Для каждого ожидающего шага runner открывает транзакцию, вызывает единый `Run context`, записывает историю и делает commit. Ошибка прекращает обработку; незавершённая транзакция откатывается, предыдущие успешные миграции сохраняются. При обрыве связи во время commit результат выясняется следующим запуском по истории, атомарной с изменениями миграции.

Подключение и транзакция принадлежат runner. Обработчики не закрывают их и не выполняют собственные BEGIN/COMMIT/ROLLBACK. Нетранзакционные операции PostgreSQL пока не поддерживаются. Отмена передаётся в операции явно. Внешние эффекты не откатываются транзакцией БД.

При ошибке в лог попадают имя миграции и SQLSTATE PostgreSQL либо тип исключения; SQL, значения данных и полный объект исключения не логируются. Исходное исключение сохраняется для отладчика. Отмена обрабатывается отдельно с кодом 130.
