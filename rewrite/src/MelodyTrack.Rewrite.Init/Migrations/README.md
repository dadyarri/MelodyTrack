# SQL-миграции

Файлы лежат непосредственно в этом каталоге и называются `0001_CreateServices.sql`: четыре цифры от `0001`, подчёркивание, имя PascalCase латинскими буквами и цифрами, расширение `.sql`. Номера уникальны; пропуски номеров допустимы. Порядок выполнения определяется номером.

SQL-файлы копируются в подкаталог `Migrations` выходного каталога сборки и публикации. Init ищет `*.sql` непосредственно в `AppContext.BaseDirectory/Migrations`, без рекурсии и без зависимости от текущего рабочего каталога. Отсутствие каталога считается ошибкой. Этот README также копируется, чтобы каталог существовал до появления первой миграции; отсутствие SQL-файлов пока допустимо.

Загрузчик проверяет имена, уникальность номеров, кодировку UTF-8 и отсутствие пустого SQL. UTF-8 BOM допустим и убирается только из текста для выполнения.

Контрольная сумма — SHA-256 исходных байтов файла, включая BOM и окончания строк, в шестнадцатеричном виде. Поэтому после выпуска миграции нельзя менять даже её форматирование; исправления добавляются новой миграцией. Для SQL в репозитории заданы окончания строк LF.

Init загружает миграции, проверяет подключение и получает сессионную advisory-блокировку PostgreSQL. Если блокировка уже занята другим Init, текущий запуск завершается с кодом 1. Выделенное соединение без pooling и multiplexing остаётся открытым до завершения работы; его закрытие освобождает блокировку, включая завершение через ошибку или отмену.

Под блокировкой Init создаёт `public.schema_migrations`, если таблицы ещё нет. Она хранит номер, имя, SHA-256 и время применения миграции (`timestamptz`). Затем Init сверяет историю с файлами: отсутствие, переименование или изменение применённой миграции считаются ошибкой. Новая миграция с номером ниже уже применённого также отклоняется; допустимые пропуски номеров не разрешают добавлять миграции задним числом.

После успешной сверки Init выполняет ещё не применённые миграции по номеру. Для каждого файла открывается отдельная транзакция: выполняется SQL, добавляется строка истории, затем выполняется commit. Ошибка прерывает обработку; незавершённая транзакция откатывается при освобождении, а уже успешно применённые миграции сохраняются. При следующем запуске они будут пропущены после сверки истории. Прерывание соединения во время commit может оставить клиенту неизвестный исход; следующий запуск определит его по истории, которая фиксируется атомарно с изменениями миграции.

Транзакцией управляет runner: SQL-файлы не должны содержать собственные `BEGIN`, `COMMIT`, `ROLLBACK` или команды вроде `CREATE INDEX CONCURRENTLY`, запрещённые внутри транзакции PostgreSQL. Специальный режим нетранзакционных миграций пока не поддерживается. Runner не разбирает SQL и не проверяет этот контракт отдельным SQL-парсером.

Перед каждой миграцией и после успешного commit выводится её имя. Ошибка применения содержит имя миграции и исходное исключение для отладчика. В лог выводится только имя миграции и SQLSTATE для ошибок PostgreSQL либо тип исключения для остальных ошибок. SQL, сообщения PostgreSQL, значения данных и полный объект исключения не логируются. Отмена не оборачивается в ошибку миграции и обрабатывается Init отдельно с кодом 130 при отмене приложения.
