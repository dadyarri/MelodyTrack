# Первый пакет импорта: источники, клиенты и контакты

`ClientImport.RunAsync` переносит первый предметный блок из `ConnectionStrings:OldDatabase` в отдельную целевую БД. Запуск обычного Init по-прежнему применяет только SQL-схему. Импорт включается явно через `--Import:Clients true`.

## Результат переноса из Aspire

Для текущего локального переноса выбран PostgreSQL Aspire с томом `melodytrack-postgres-data`. Первый пакет успешно перенесён 10.11.2026 в отдельную новую PostgreSQL 17. Прежняя цель rewrite на PostgreSQL 18 не изменялась. Это перенос клиентского блока выбранной локальной базы, не переключение production и не перенос остальных предметных областей.

| Результат | Первый запуск | Повторный запуск |
| --- | --- | --- |
| Код выхода | 0 | 0 |
| Источники | Вставлено 6 | Совпало 6, вставок нет |
| Клиенты | Вставлено 49 | Совпало 49, вставок нет |
| Контакты | Вставлено 193 | Вставок нет |
| Предупреждения | Нет | Нет |

Init применил все 13 текущих SQL/C#-миграций. Дополнительная read-only сверка подтвердила поля всех 49 клиентов, принадлежность и точные расшифрованные значения 193 контактов и 6 источников. Повторный импорт сохранил клиентские строки, шифротекст и соответствия ID без изменений. Снимки исходных `ClientSources`, `Clients`, `ClientContacts` и `__EFMigrationsHistory` до и после обоих запусков совпали; источник открывался только для чтения.

Локальные ресурсы цели:

- Контейнер: `melodytrack-rewrite-import-postgres`.
- Постоянный Docker volume: `melodytrack-rewrite-import-postgres-data`.
- Подключение без пароля: `Host=127.0.0.1;Port=32769;Database=melodytrack_rewrite;Username=postgres`. Порт относится к текущему контейнеру.
- Подключения и ключи: `.env.import.local` в корне rewrite, права `0600`, файл игнорируется Git. Новый ключ целевой базы хранится здесь; его необходимо сохранять вместе с доступом к резервным копиям данных. Пароли и значения ключей в отчёты не включены.

Init и API не загружают `.env` автоматически. Перед их запуском конфигурация текущего переноса загружается в окружение shell:

```sh
set -a
. ./.env.import.local
set +a
```

Это окружение переопределяет `ConnectionStrings:Database` и `ConnectionStrings:OldDatabase` из appsettings; без него останутся прежние подключения. При пересоздании контейнеров следует актуализировать назначенные порты. Сам импорт выполнен актуальным C# Init командой `dotnet run --no-build --project src/MelodyTrack.Rewrite.Init -- --Import:Clients true` дважды. Перед ним сборка всей solution завершилась успешно: `.artifacts/agent-checks/20261110T200620-7ca63896/report.json`. Итоги импорта и сверки: `.artifacts/client-import-aspire/report.json`. Обычные автоматические тесты в этой операции не запускались.

## Запуск

Init использует следующие настройки из стандартной конфигурации .NET:

| Настройка | Назначение |
| --- | --- |
| `ConnectionStrings:OldDatabase` | Источник, открываемый только для чтения |
| `ConnectionStrings:Database` | Отдельная целевая БД |
| `Import:LegacyKeys:<original-version>` | Исходные строковые master key, по всем нужным версиям |
| `PersonalData:CurrentKeyVersion` | Версия нового ключа |
| `PersonalData:Keys:<version>` | Ключи целевого хранилища: 32 случайных байта в Base64 |

Секреты не передаются в командной строке и не включаются в отчёт. В стандартном провайдере переменных среды разделитель `:` заменяется на `__`; например, `Import__LegacyKeys__v1`. Файл с реальными ключами не следует коммитить. Для CLI-импорта ключи целевой БД должны быть сохранены в её внешней секретной конфигурации, иначе записанные значения окажутся недоступны.

```sh
DOTNET_ENVIRONMENT=Development dotnet run --project src/MelodyTrack.Rewrite.Init -- --Import:Clients true
```

Коды выхода: `0` — пакет завершён без предупреждений; `2` — корректные строки перенесены, но пакет требует ручного разбора; `1` — ошибка; `130` — отмена. Предупреждения не означают успешный перенос пропущенных клиентов. Команда не предназначена для одновременной работы с новым приложением: импорт выполняется до переключения.

## Границы и повторный запуск

Источник открывается с `default_transaction_read_only=on`; чтение идёт в одной транзакции `REPEATABLE READ READ ONLY`. Время и даты читаются с UTC и ISO/YMD. SQL-миграции никогда не получают исходное соединение. Целевая БД с `__EFMigrationsHistory` отклоняется. Первый пакет читает весь клиентский срез в память; это проверено на небольшой фикстуре и ещё не является механизмом импорта произвольных объёмов порциями.

`0002_CreateImportMappings.sql` создаёт две служебные таблицы:

| Таблица | Назначение |
| --- | --- |
| `import_id_map` | Старые 16 байт ULID + таблица + часть записи → новый UUIDv7 |
| `import_contact_kinds` | Четыре исходных поля Phone/Email/Telegram/Vk → новые виды контактов |

Одинаковые названия источников не объединяются. Историческая общая строка контактов разделяется по клиентам-владельцам. В карте контакта `part` содержит старый ID владельца и имя поля: повтор одного переноса использует те же новые ID, а разные владельцы получают отдельные контакты. Эти таблицы относятся к одному согласованному источнику переноса; переиспользовать целевую БД для другой установки нельзя.

Целевая транзакция сериализует импорты advisory-блокировкой. Каждый источник и клиент обрабатываются под savepoint. Если клиент не проходит проверку, откатываются вся его карточка, контакты и новые соответствия ID. Корректные объекты других клиентов могут сохраниться. Повторно существующие строки не перезаписываются: импорт сравнивает их с исходником и расшифровывает целевые контакты в их контексте. Расхождение с уже изменённой целью выдаётся на ручной разбор.

После новой записи те же пообъектные сравнения выполняются до commit. Сохраняются исходные ФИО, дата рождения, nullable источник, момент создания, признак закрытого лида и точное представление контактов. PostgreSQL infinity и технические минимальные времена переносятся без замены текущим временем: исходное текстовое представление даты/момента сохраняется явным SQL-приведением. Закрытый лид не превращается в архив. Пустые контактные поля дают пустой список без фиктивных значений.

Старый `enc:` сначала читается `LegacyPersonalDataReader`, после предметной проверки значение шифруется для новых ID через `ClientDataProtection`. Копировать исходный шифротекст в новую схему нельзя. Непустые неподходящие ссылки не дополняются URL автоматически. Пробелы, которые нельзя сохранить через текущую модель имени, тоже требуют ручного решения.

Отчёт содержит таблицу, номер строки в сортировке по исходному bytea ID, поле и код причины; имена, контакты, ключи и шифротекст в него не попадают. Номер строки относится к неизменяемому исходному срезу, а не к изменяемой production-БД. В консоль выводятся только счётчики и группировки кодов. Несвязанные контактные строки остаются в источнике; они не присваиваются случайному клиенту и не удаляются.

## Автоматическая проверка на Testcontainers

`ClientImportTests.Run_ReadOnlySource_ReconcilesImportedClientsAndReplaysWithoutDuplicates` работает с двумя отдельными БД в PostgreSQL 17 Testcontainer. Источник создаётся по минимальной схеме читаемого клиентского блока, наполняется синтетическими данными и переводится в read-only. Цель получает настоящие SQL-миграции Init. Исходный тестовый ключ и зашифрованный контакт являются публичной фикстурой, новый ключ генерируется в памяти.

Сценарий проверяет содержимое расшифрованных целевых контактов, перенос полей клиентов, стабильность ID и отсутствие дублей при повторе, неизменность исходных строк и запрет записи в источник. Он включён в обычный набор: `Explicit`, внешние JSON-файлы, переменные среды и ключи развёрнутой системы ему не нужны. Требуется Docker. Прежний дублирующий `ClientImportLiveTests` удалён.

Контейнерная фикстура проверяет логику импорта, но не наличие подходящих ключей и качество данных конкретной production-БД. Проверка реального источника остаётся отдельной операцией с отдельным разрешением.

## Проверенные локальные источники

Диагностика 10.11.2026 различила две базы. Aspire переопределяет `Database__ConnectionString` ссылкой на PostgreSQL с томом `melodytrack-postgres-data`; строка из старого launchSettings совпадает с настроенным `OldDatabase`, но не с фактическим подключением Aspire.

| Наблюдение | Прежний `OldDatabase` из appsettings | База Aspire |
| --- | --- | --- |
| PostgreSQL (`server_version_num`) | `180006` | `160015` |
| EF-миграции | 55 | 53 |
| Клиенты | 60 | 49 |
| Строки контактов | 122 | 49 |
| Несвязанные строки контактов | 62 | 0 |
| Зашифрованные поля связанных контактов | 240 | 193 |
| Успешная расшифровка ключом старых launchSettings | 0 из 240 | 193 из 193 |
| Успешная расшифровка подходящим ключом Rider | 240 из 240 | Не проверялась |

Ключ в профилях Backend `http` и Init `development` одинаковый. Для `OldDatabase` подходит другой ключ версии `v1` из одной из конфигураций `../.idea/.idea.MelodyTrack/.idea/workspace.xml`. Им также успешно расшифрованы все 212 зашифрованных полей несвязанных контактов: всего 452 из 452 полей этой базы. Значения ключей не переносятся в документацию. При запуске импорта подходящий ключ передаётся через `Import:LegacyKeys:<version>`; чтение IDE workspace самим импортёром не требуется.

Проверка выполнена отдельным диагностическим Python-скриптом через libpq: подключения с `default_transaction_read_only=on`, транзакции `REPEATABLE READ READ ONLY`, AES-GCM с тем же SHA-256-преобразованием master key, что у `LegacyPersonalDataReader`, и проверкой UTF-8. Ключи, шифротекст и открытые значения обрабатывались только в памяти; выводились обезличенные счётчики. Это проверка доступности ключей, а не запуск C#-импортёра или приёмка целевых моделей. Базы и настройки подключений не изменялись; миграции, импорт и автоматические тесты в этой диагностике не запускались.

Блокер доступности ключей для обеих локальных баз снят. Результат выполненного переноса выбранной базы Aspire приведён выше. Для прежнего `OldDatabase` остаётся ручной разбор 62 несвязанных строк; он источником текущего переноса не является. Ни одна из этих локальных баз не подтверждена как production-копия D-415/D-416 (PostgreSQL 17 / 49 миграций до `Stage14TimedVacations`).
