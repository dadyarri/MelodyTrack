# Первый пакет импорта: источники, клиенты и контакты

`ClientImport.RunAsync` переносит первый предметный блок из `ConnectionStrings:OldDatabase` в отдельную целевую БД. Запуск обычного Init по-прежнему применяет только SQL-схему. Импорт включается явно через `--Import:Clients true`.

## Запуск

Init использует следующие настройки из стандартной конфигурации .NET:

| Настройка | Назначение |
| --- | --- |
| `ConnectionStrings:OldDatabase` | Источник, открываемый только для чтения |
| `ConnectionStrings:Database` | Отдельная целевая БД |
| `Import:LegacyKeys:<original-version>` | Исходные строковые master key, по всем нужным версиям |
| `PersonalData:CurrentKeyVersion` | Версия нового ключа |
| `PersonalData:Keys:<version>` | Ключи целевого хранилища: 32 случайных байта в Base64 |

Секреты не передаются в командной строке и не включаются в отчёт. В стандартном провайдере переменных среды разделитель `:` заменяется на `__`; например, `Import__LegacyKeys__v1`. Файл с реальными ключами не следует коммитить. Для CLI-импорта ключи целевой БД должны быть сохранены в её внешней секретной конфигурации, иначе записанные значения окажутся недоступны.

```sh
DOTNET_ENVIRONMENT=Development dotnet run --project src/MelodyTrack.Rewrite.Init -- --Import:Clients true
```

Коды выхода: `0` — пакет завершён без предупреждений; `2` — корректные строки перенесены, но пакет требует ручного разбора; `1` — ошибка; `130` — отмена. Предупреждения не означают успешный перенос пропущенных клиентов. Команда не предназначена для одновременной работы с новым приложением: импорт выполняется до переключения.

## Границы и повторный запуск

Источник открывается с `default_transaction_read_only=on`; чтение идёт в одной транзакции `REPEATABLE READ READ ONLY`. Время и даты читаются с UTC и ISO/YMD. SQL-миграции никогда не получают исходное соединение. Целевая БД с `__EFMigrationsHistory` отклоняется. Первый пакет читает весь клиентский срез в память; это проверено на небольшой фикстуре и ещё не является механизмом импорта произвольных объёмов порциями.

`0002_CreateImportMappings.sql` создаёт две служебные таблицы:

| Таблица | Назначение |
| --- | --- |
| `import_id_map` | Старые 16 байт ULID + таблица + часть записи → новый UUIDv7 |
| `import_contact_kinds` | Четыре исходных поля Phone/Email/Telegram/Vk → новые виды контактов |

Одинаковые названия источников не объединяются. Историческая общая строка контактов разделяется по клиентам-владельцам. В карте контакта `part` содержит старый ID владельца и имя поля: повтор одного переноса использует те же новые ID, а разные владельцы получают отдельные контакты. Эти таблицы относятся к одному согласованному источнику переноса; переиспользовать целевую БД для другой установки нельзя.

Целевая транзакция сериализует импорты advisory-блокировкой. Каждый источник и клиент обрабатываются под savepoint. Если клиент не проходит проверку, откатываются вся его карточка, контакты и новые соответствия ID. Корректные объекты других клиентов могут сохраниться. Повторно существующие строки не перезаписываются: импорт сравнивает их с исходником и расшифровывает целевые контакты в их контексте. Расхождение с уже изменённой целью выдаётся на ручной разбор.

После новой записи те же пообъектные сравнения выполняются до commit. Сохраняются исходные ФИО, дата рождения, nullable источник, момент создания, признак закрытого лида и точное представление контактов. PostgreSQL infinity и технические минимальные времена переносятся без замены текущим временем: исходное текстовое представление даты/момента сохраняется явным SQL-приведением. Закрытый лид не превращается в архив. Пустые контактные поля дают пустой список без фиктивных значений.

Старый `enc:` сначала читается `LegacyPersonalDataReader`, после предметной проверки значение шифруется для новых ID через `ClientDataProtection`. Копировать исходный шифротекст в новую схему нельзя. Непустые неподходящие ссылки не дополняются URL автоматически. Пробелы, которые нельзя сохранить через текущую модель имени, тоже требуют ручного решения.

Отчёт содержит таблицу, номер строки в сортировке по исходному bytea ID, поле и код причины; имена, контакты, ключи и шифротекст в него не попадают. Номер строки относится к неизменяемому исходному срезу, а не к изменяемой production-БД. В консоль выводятся только счётчики и группировки кодов. Несвязанные контактные строки остаются в источнике; они не присваиваются случайному клиенту и не удаляются.

## Проверка с OldDatabase — 01.11.2026

Пользователь добавил `OldDatabase` в Development-конфигурацию Init. Указанная БД доступна: PostgreSQL `18.6` (server_version_num `180006`), 55 EF-миграций, последняя `20260731181524_AddSavedClientPortalIdentities`. Это ранее описанная локальная фикстура, а не принятый production-референс PostgreSQL 17 / 49 миграций до `Stage14TimedVacations`. Результат не выдаётся за приёмку production-переноса. Требуемые столбцы первого клиентского блока в фикстуре присутствуют.

Явный `ClientImportLiveTests` использовал эту БД только для чтения и отдельный PostgreSQL 17 Testcontainer для цели. Настроенная пользователем целевая БД не изменялась. Случайный целевой ключ существовал только в памяти теста; тестовая БД уничтожена вместе с контейнером.

| Наблюдение | Результат |
| --- | --- |
| Исходные источники | 9 |
| Исходные клиенты | 60 |
| Исходные строки контактов | 122 |
| Несвязанные строки контактов | 62 предупреждения `orphan_contact` |
| Все зашифрованные поля исходных контактов | 452, включая несвязанные строки |
| Поля связанных клиентов, не прочитанные без исходных ключей | 240 предупреждений `source_decryption_failed` |
| Перенесено в тестовую цель | 9 источников, 0 клиентов, 0 контактов |
| Повторный запуск | 9 источников совпали, повторных вставок нет |
| Итог явного теста | Отказ: отсутствуют исходные ключи; перенос клиентов не принят |

Первоначально исходные ключи в просмотренной конфигурации отсутствовали. По указанию пользователя ключи затем прочитаны из старого `MelodyTrack.Init/Properties/launchSettings.json`, профиль `development`, и переданы только в окружение дочернего процесса теста как `Import__LegacyKeys__<original-version>`. Значения не записывались в новые конфигурационные файлы и не выводились в отчёт. Повторный явный тест также завершился отказом: 9 источников, 0 клиентов и 240 отказов расшифровки.

Дополнительно на одном зашифрованном поле в памяти проверены профили Init и Backend текущего репозитория и референсного worktree `1636c2c`. Версии ключей совпадают с исходной записью, но ни один из этих ключей не проходит AES-GCM-проверку подлинности. Проверка выполнялась с read-only доступом к источнику, без вывода шифротекста, открытого значения или ключевого материала. Таким образом, препятствие — отсутствие подходящего ключа именно этой копии БД, а не передача переменных окружения. Нужен путь к фактической исходной секретной конфигурации; значение ключа в чат присылать не требуется.

После получения подходящего ключа явный тест проверит содержимое контактов, допустимость ссылок и повторный перенос. Наличие 62 несвязанных строк останется отдельным основанием ручного разбора.

Фокусный набор схемы/enum/защиты/импорта: **93 passed**. Проверки конфигурации API: **4 passed**. После добавления независимости от DateStyle/часового пояса повторены все проверки импортёра: **7 passed**. Явный тест OldDatabase: **1 failed** из-за недоступных исходных ключей. Проверки используют настоящие SQL-миграции и PostgreSQL 17, а не копию схемы в тестах.

Явный тест не выполняется в обычном прогоне. Путь к локальной конфигурации передаётся отдельно, без копирования её содержимого в артефакты:

```sh
MELODYTRACK_IMPORT_SOURCE_CONFIG=/absolute/path/to/init/appsettings.Development.json \
dotnet test --project tests/MelodyTrack.Rewrite.Init.Tests/MelodyTrack.Rewrite.Init.Tests.csproj \
  --filter-class '*ClientImportLiveTests' --explicit only --show-live-output on
```

Тест дополнительно читает стандартные переменные среды; ключи можно задать через `Import__LegacyKeys__<version>`. Этот тест всегда создаёт отдельную цель PostgreSQL 17 и не использует `ConnectionStrings:Database` для записи.
