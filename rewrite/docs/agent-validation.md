# Проверка агентной инфраструктуры

Сценарии ниже — документальная симуляция маршрутов, без изменения приложения и без утверждения бизнес-правил. Они дополняют автоматические тесты парсеров/процессов, не заменяют реальные продуктовые проверки.

| Вход | Маршрут и результат | Решение пользователя / автономность |
|---|---|---|
| Новое правило противоречит принятому | analyst показывает два ID и контрпример, critic проверяет независимо | зависимое поведение ждёт решения пользователя |
| Старый код содержит правило вне новой спецификации | rewrite-requirements фиксирует ref/path и «актуальность неизвестна» | нет автоматического переноса; независимое исследование продолжается |
| Backend/UI по-разному трактуют состояние | developer сравнивает request/state/error contract с правилами; QA воспроизводит | техническая ошибка исправляется автономно; неизвестная семантика согласуется |
| QA нашёл неописанный случай | QA фиксирует вход и отсутствующий ожидаемый исход | analyst готовит вопрос, QA не придумывает ответ |
| Неоднозначность обнаружена в реализации | developer останавливает зависимую часть и передаёт конкретный вопрос | остальная согласованная работа продолжается |
| Технический рефакторинг | основной агент сохраняет наблюдаемые инварианты/контракт, semantic refactoring skill по необходимости | бизнес-согласование не требуется; проверки по разрешению |
| Нужен перенос данных | migration specialist: source→target, identity/history, partial/retry/recovery | неизвестные преобразования/разрушительный запуск согласуются отдельно |
| Небольшая исправленная ошибка | основной агент: правило, воспроизведение, регрессия и исправление | не запускает восемь ролей; после готовности — разрешённый scope |
| Build успешен, один тест падает | CLI сохраняет test_failed, ненулевой исход и native XML, QA открывает details | нет статуса «всё прошло» |
| Runner падает без стандартного отчёта | CLI сохраняет exit code, incomplete/tool_error и полный лог | не классифицирует как продуктовый баг без доказательств |
| Тысячи успехов и несколько ошибок | XML parser считает все; summary выводит до пяти failures, остальные через details --all | полные сведения сохраняются, LLM не читает весь лог |
| Повтор failed methods проходит | новый run с parent_run и subset_passed; исходный отчёт остаётся | полный scope ещё не подтверждён |

## Фактическая проверка

Команды и результаты итоговой проверки фиксируются после завершения пачки. Продуктовые сборки, миграции и тесты приложения не нужны для этой задачи и не запускались. Проверки Python используют синтетические XML и временные процессы/каталоги.

Структурный валидатор проверяет локальные TOML, name/description skills, уникальность имён, ссылки и упоминания новых skills. Это не доказательство обнаружения каждым IDE-клиентом. Локальный CLI 0.165.0 установлен; официальные схемы просмотрены. Регистрация custom agents в новой интерактивной сессии требует проверки в соответствующем клиенте, без запуска дополнительной платной LLM-сессии ради smoke test.

### Результаты 07.11.2026

- `python3 scripts/check_agent_infrastructure.py`: 5 skills, 8 agents,
  0 structural errors; TOML и локальные ссылки корректны.
- Bundled `skill-creator/scripts/quick_validate.py` вызван через
  `validate_skill` для всех пяти каталогов: каждый `Skill is valid!`.
- `python3 -B -m unittest discover -s scripts/tests -v`: 20 tests, OK.
  Покрыты успех, разные/повторяющиеся failures, большой отчёт, отсутствующий
  executable, пустой/битый/частичный XML, timeout, interruption, ненулевой код
  при успешном XML, нулевой код при failed XML, subset и неизменность original.
- `python3 scripts/agent_checks.py plan --scope all`: без выполнения продукта
  сформированы solution build и три MTP-проекта с native XML и `--explicit off`.
- `git diff --check`: без замечаний.
- Независимый read-only forward-test требований/verification/critic/QA:
  старые зелёные Subscription tests не разрешают новые операции вопреки
  D-428/D-450; успешный rerun не меняет исходный FAIL; технический rename
  без изменения контракта не требует бизнес-согласования. Существенных
  конфликтов инструкций не выявлено; 13 ссылок аудита также проверены отдельно.

При первой установке валидатор обнаружил файлы на один уровень выше ожидаемого;
размещение исправлено на `.agents/skills/` и `.codex/agents/`, затем проверка
повторена успешно. Проверка dotnet-интеграции на реальном запуске и обнаружение
ролей новой IDE-сессией здесь не выполнялись; это явные границы доказательства.
