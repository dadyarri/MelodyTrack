# Вход суперпользователя

## Цель

Устранить ошибки «Нет доступа» при загрузке и использования passkey при входе.

## Статус

Правка Vite завершена и принята пользователем. Разрешён отдельный коммит этой задачи; push не запрошен.

## Источники и выполненное

- Требования: [AUTH-002/006/010](../../../../specification/authentication.md); адрес разработки — [web README](../../../web/README.md#запуск).
- Ветка `design/melodytrack-v2`, существующий большой прикладной diff просмотрен в части авторизации.
- Пользователь открывает `http://127.0.0.1:5174/sign-in` в Zen (Firefox).
- Локальная конфигурация задаёт RP ID `localhost`, origins `http://localhost:5174` и `http://localhost:5280`. IP не соответствует RP ID; проверка `StaffSessionCookies.HasTrustedOrigin` отклоняет такой origin при восстановлении сессии.
- Рекомендован вход через `http://localhost:5174/sign-in`. Доступ к данным аккаунта и изменение его настроек не выполнялись.
- По запросу пользователя Vite явно слушает `localhost` и перенаправляет HTML-навигацию GET/HEAD с loopback IP на `http://localhost:5174`, сохраняя путь и query. API-запросы этим middleware не перенаправляются. Документация запуска обновлена.

## Проверки и ограничения

Статически сверены WebAuthn frontend, проверка origin и локальные RP/origins без вывода секретов. Итоговый diff Vite просмотрен вручную. Тесты, сборки и frontend verification не запускались: отдельного разрешения нет. Успешный вход в браузере ещё не подтверждён.

## Следующее действие

В согласованном объёме реализации ничего. При повторном отказе входа выяснить наличие системного выбора ключа и конкретный этап отказа без получения токенов/секретов. Не расширять доверенные origins и не менять RP ID для обхода проверки.
