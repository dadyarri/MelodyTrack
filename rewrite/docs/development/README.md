# Сохранение контекста между сессиями

Это технический процесс разработки, а не новая спецификация поведения продукта.

Не создавать параллельные `docs/architecture.md`, `docs/specifications/` или каталог ADR ради формы. Использовать существующий реестр решений. Отдельное решение нужно лишь для существенного обоснования, которого нет в источниках: заголовок, статус, контекст/проблема, решение, альтернативы, последствия/компромиссы, связи; ссылка на него помещается в существующий реестр. Не реконструировать мотивы исторических решений без свидетельств.

При значимой функциональности сохранять в соответствующем разделе спецификации цель/границы, функциональные и существенные нефункциональные требования, ограничения, сценарии, критерии приёмки и связанные решения. Утверждения, предположения и открытые вопросы имеют разные статусы. Новые бизнес-решения требуют подтверждения по AGENTS; снимок задачи не даёт права считать предложение утверждённым.

## Снимки и контрольные точки

Общее состояние ведёт только основной агент. `current-task.md` — небольшой снимок с разделами, уже заданными в файле, ориентир 100–150 строк. Обновлять после значимого этапа, существенного решения, блокера, результатов проверок и перед переключением/передачей работы. Между этими точками не вести журнал действий. Указывать факты, незавершённые изменения и причины, точные следующие шаги, выполненные и ещё необходимые проверки; результаты прежних запусков не подтверждают текущий diff.

При нескольких независимых незавершённых задачах основной агент сохраняет снимки в `tasks/<краткое-имя>.md` с теми же разделами, а `current-task.md` делает кратким индексом: цель, статус, ссылка, следующее действие для каждой задачи. Каталог создавать только при реальной необходимости. Длительная подзадача может иметь отдельный временный handoff только по назначению координатора; он не дублирует общее состояние и после интеграции удаляется либо включается в общий снимок. Не создавать память на каждый вызов агента.

Завершённый снимок очистить от промежуточных сведений, отметить завершение, оставить ссылки и важные ограничения. При следующей задаче заменить его; бесконечного архива завершённых снимков не вести. Перед переключением сохранить незавершённую задачу отдельно. Значимые решения пользователя, ещё не перенесённые в постоянные документы, явно отметить вместе с местом переноса.

## Ручная передача

«Сохрани контекст для новой сессии»: проверить ветку/status/diff, обновить снимок и постоянные источники в разрешённой области, назвать блокеры и конкретное следующее действие, сообщить пути для продолжения.

«Продолжи задачу по docs/development/current-task.md»: прочитать применимые AGENTS и снимок, проверить фактическую ветку/status/diff и связанные требования, устранить расхождения и продолжить с актуального следующего действия. Не требовать повторения уже сохранённого контекста. При неизвестной задаче явно писать «Активная задача не зафиксирована», не выводить её из наличия файлов.

## Git и безопасность

Снимок описывает общую проектную задачу, а не персональную память; он хранится рядом с уже версионируемыми планами/аудитами в `docs/`. Это выбранная модель для текущего процесса rewrite: постоянные документы и общий снимок доступны другим сессиям через Git после отдельно разрешённого коммита. Новых игнорирований и локального хранилища не требуется. Личные заметки и настройки сюда не переносить. Полные отчёты остаются в уже игнорируемом `.artifacts/`; ссылка на локальный артефакт не гарантирует его наличие в другом checkout, поэтому краткий итог проверки должен быть самодостаточным.

Секреты, исходные персональные данные, значения конфигурации доступа, полные логи и транскрипты не сохранять. Не коммитить и не отправлять автоматически. Текущие указания пользователя задают объём задачи; документация не разрешает самостоятельно продолжать следующую порцию или обходить ограничения проверок.
