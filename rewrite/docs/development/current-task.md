## Согласованный результат

- Основной источник — [спецификация аналитики](../../../specification/analytics-and-dashboards.md), направление D-542. Это ещё не полностью утверждённый контракт реализации; открытые и отложенные вопросы хранятся в её разделе «Открытые решения».
- D-546: статистика и аналитика требуют интернета, включая чтение виджетов/результатов и редактирование запросов. Это явное исключение из D-449 только для этой области; требования остальных функций сохраняются. Согласованы ссылки в архитектуре, design-guide и реестре решений.
- Календарные расчёты, границы периодов и отображение аналитики используют фиксированную Europe/Moscow по D-141; абсолютные отметки хранятся/передаются в UTC по D-133.
- D-542 принадлежит аналитике из PR. Номера офлайн-решений исправлены на D-543–D-545 и сохранены в отдельной ветке; при объединении сохранить эти ID и исключение D-546.
- D-547: только страницы статистики; на каждой свой тематический дашборд, общий для всех пользователей страницы, с видимостью каждого виджета отдельно по роли. У сотрудника одна роль. Рабочие экраны и быстрые действия не включаются в конструктор; персональных/ролевых копий дашборда нет.
- D-548: отдельные разрешения редактирования (запросы, компоновка и оформление), настройки видимости и управления версиями. По умолчанию только суперы; ручная выдача через персональные исключения. Редактирование не даёт прав на видимость, публикацию или откат.
- D-549: модель «отчёт хранит запрос и версии; виджет отображает отчёт». Все его виджеты обновляются, закрепление на старой версии запрещено. Сохраняются все версии и полные тексты запросов. Настройки тоже версионируются и откатываются; откат настроек не закрепляет отчёт на старой версии. Специальный сценарий одновременного редактирования не нужен. Единицы публикации и разрешения конкретизированы D-558/D-559.
- D-550: максимально полный каталог хранимых предметных данных согласно спецификации; права задаются согласованной матрицей. Финансовые правила не изменены: сумма пары по участникам, занятость преподавателя один раз. Отдельное утверждение «пара всегда ровно вдвое дороже» не вводилось: персональные цены и резервы D-480/D-481 сохраняются.
- D-551: календарные даты до текущего времени; три календарных месяца — текущий неполный и два предыдущих полных. Пользователь отдельно подтвердил явное будущее для прогнозов D-184/D-535. Даты занятий — начало, платежей/расходов — внесение D-430. Рабочие дни — по выбранному сотруднику с учётом выходных и отпусков, ссылки `@Фамилия Имя`/`@я`. Грамматика и точные нижние границы ещё открыты.
- D-552: отрицательный лимит одобрен, берёт последние N строк отсортированного результата, сохраняя порядок. Обратная сортировка с положительным лимитом даёт обратный порядок вывода и не полностью эквивалентна.
- Пользователь вернул отложенные вопросы текстом другого ИИ, с приоритетом наших уже согласованных требований при конфликтах. Совместимая часть интегрирована как D-553–D-556; противоречащие аудитории, сокращение истории версий и схема прав не перенесены. Это не полное утверждение готовности к реализации.
- D-553: фиксированные стадии DSL, несколько `где` через `и`, `имея` после агрегации, группировка по идентичности, атрибуты сгруппированной сущности, условный `количество(условие)`, параметры с обязательным вводом без default, правила пустого результата/null/деления на ноль. Не связанные с преподавателем `@я` не дают совпадений; арифметика с объектной ссылкой ошибочна. Значения агрегатов уточнены D-562, логические выражения с null и лексические детали ещё открыты.
- D-554: таблица/число/столбцы/линия/круговая, CSV исходных значений при праве экспорта, открытие конкретной карточки без универсальной расшифровки агрегатов. Пропуски `ноль/пусто/пропустить`, default `пусто` при отсутствии иной семантики метаданных. Кэш по ревизии/параметрам/правам/области/календарю; fallback только совместимого результата, без офлайн-чтения.
- D-555: ограниченный типизированный план до SQL, доступы до агрегации, запрет скрытого усечения исходного набора ради лимита результата. Пользователь явно оставил все численные лимиты предложениями до нагрузочной проверки; таблица кандидатов находится отдельно от утверждённых правил в основном документе.
- D-556: первый выпуск аналитики с CodeMirror 6 и бейджами ссылок, параметрами, представлениями, публикацией и полной историей. Произвольные рабочие периоды DSL отложены с сохранением D-551; рабочая ёмкость обязательных отчётов не откладывается. Первый выпуск аналитики не равен первому переключению приложения. Курсы/ДЗ отложены D-446, чужая свободная практика закрыта D-364/D-500. Наличие необходимой истории в коде и production не проверялось.
- D-557: пользователь подтвердил отдельное разрешение CSV, по умолчанию только суперам, с персональными исключениями. Оно не расширяет область чтения; D-425 для экспорта прежних расходов сохраняется. Право добавлено в матрицу доступа.
- D-558: независимая публикация отчёта (DSL, параметры, типизированная схема, виды), атомарная публикация всего дашборда (виджеты, связи, параметры, компоновка, оформление, видимость). Проверка всех опубликованных потребителей; черновики не влияют на пользователей.
- D-559: публикация/откат требуют управления версиями и разрешений по фактическому diff. Пользователь отдельно подтвердил сохранение трёх прав D-548, администратор получает их персонально. Откат — новая ревизия без переписывания истории, проверка зависимостей и аудит; отказ целиком при нехватке права.
- D-560: обязательны отчёты работы/нагрузки, выручки/денежных потоков, долга, привлечения/активности/удержания клиентов. Источник — `../docs/statistics-methodology.md`, адаптированный к нормативным правилам rewrite; исходный документ старого приложения не переписывался. Пользователь явно подтвердил приоритет финансовых правил rewrite: независимые долги услуг и личная стоимость с резервами/скидками. Количества/статусы — по участиям клиентов; загрузка — по общим встречам (отдельный ответ пользователя). Сложные показатели предоставляет каталог/общие бизнес-сервисы, не второй DSL-расчёт. Сохраняются 2 года выбранного окна и 100 строк клиентских таблиц; полные KPI/накопительная история не усекаются. Интеграционные проверки методики — требование будущей реализации.
- D-561: 30 дней от 00:00 29 дней назад, понедельник, полуоткрытые интервалы; явная последняя дата включительна через начало следующего дня; один текущий момент на запрос/обновление дашборда.
- D-562: доля true/all с null в знаменателе, пустая — null; min/max/avg игнорируют null, без значений — null; сумма без значений — 0; деньги decimal; типы проверяются до исполнения.
- D-563: версия каталога, проверки опубликованных зависимостей в CI/подготовке обновления, миграция/совместимое определение до активации; неуспех запрещает активацию, работающая версия продолжает работу. Неисправный виджет после обновления изолируется, запуск приложения не блокируется одним отчётом; бессрочная поддержка всех каталогов не нужна.
- D-564: отпуск сотрудника исключает фактическое пересечение с рабочим временем (2 часа из 8 — 25%, остаётся 6 часов); отпуск вне рабочих интервалов не уменьшает ёмкость. Для риска/потери клиента пользователь отдельно выбрал доли календарных суток, а не рабочий календарь: 6 часов исключают 0,25 дня. Частичные отпуска не округляются до полных дней; пересечения не учитываются повторно. Неоднозначность исходной методики закрыта для аналитики rewrite, добавлены AN-43/44.

## Проверки

- Базовая пачка требований просмотрена независимым domain_critic: разрешения, одна роль, финансовые даты, прогноз, стоимость пары и модель отчёт → виджет. Для интеграции D-553–D-556 проведено отдельное независимое ревью DSL, результатов, кэша, ограниченного плана и границ первого выпуска; реализация и наличие данных не проверялись. Выявленный пробел в разрешении CSV закрыт ответом пользователя D-557 и точечным обновлением основным агентом. Пример активности уточнён до участия клиента, чтобы не смешивать его со встречей. `git diff --check` без замечаний; сборки и тесты для Markdown не запускались.
- D-558–D-563 и исходный запрос проверены независимым domain_critic до интеграции и финальным чтением изменённой спецификации. Ключевые требования согласованы; замечания по полноте методики устранены основным агентом: доли всех статусов, почасовая таблица, расходы по статьям, средняя выручка, клиентские частота/пожизненная выручка/интервалы. Исправлено название количества на участия. Матрица/реестр и последние точечные дополнения, включая D-564, просмотрены основным агентом; `git diff --check` прошёл. Проверка фактических расчётов, кода и production-данных не выполнялась.
- Проверены разделение Git diff и сохранность исходных офлайн-файлов относительно резервной копии; они сохранены в коммите отдельной ветки. PR подтверждён как MERGED, локальная ветка обновлена fast-forward.
- Тесты, сборки, линтеры и verification pipeline для этой операции не запускались. Проверка текста — `git diff --check`.
- У PR провалились backend compile/verify: restore старого приложения блокируется NuGet audit для уязвимых зависимостей. PR меняет Markdown; успешную backend-проверку не заявлять. [Запуск CI](https://github.com/dadyarri/MelodyTrack/actions/runs/43941171328).

Не переходить к реализации до утверждения соответствующей порции требований.
