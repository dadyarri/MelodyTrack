# Текущая задача

## Цель и статус

Ветка `feature/offline-v2`. Новая порция: устранить предупреждение Vite о большом чанке реальным разделением кода и начать проектирование офлайн-изменений уже для текущих возможностей. Пользователь выбрал проектирование изменений, а не ограничение первой порции оболочкой/чтением, и отдельно разрешил итоговый `npm run verify:fix`.

Разделение кода и начальная порция офлайна завершены и проверены: зашифрованное хранилище, жизненный цикл входа/выхода, черновик нового клиента и ручной повтор устойчивой команды создания. Пользователь разрешил итоговые frontend и browser scopes; оба завершились успешно. По запросу пользователя офлайн-порция сохраняется отдельным локальным коммитом в этой ветке; push не поручен.

Уточнены требования следующего объёма: ранее полученные серверные данные должны кэшироваться локально. В `docs/offline-sync.md` выделена следующая техническая порция (каталог, открытые карточки, справочники) с ограничениями полноты поиска. D-545: подтверждённый экстренный сброс пароля допускает удаление всей локальной работы; обычная смена и ошибка расшифровки не дают такого основания. В этом уточнении изменены только документы, реализация кэша и серверного признака сброса ещё отсутствует. Прежние проверки относятся к завершённой реализации, новые автоматические проверки не запускались.

Аналитика прорабатывается отдельно в `design/melodytrack-v2` по PR #14; D-542 зарезервирован за этим PR, D-543–D-545 принадлежат офлайн-порции. Эта ветка не включает текст PR и локальные уточнения аналитики. При последующем объединении сохранить подтверждённое исключение статистики из офлайна, включая чтение виджетов и редактирование запросов.

## Согласованный результат

- Порог предупреждения Vite не меняется; предупреждения не подавляются. React, Kiota, иконки, UI и прочие зависимости разделяются через Rolldown `codeSplitting`; `entriesAware` сохраняет разделение по точкам загрузки, `maxSize` делит крупные группы исходных модулей. Учитываются порядок исполнения и отсутствие рекурсивного захвата чужих зависимостей.
- Каталог клиентов и рабочая страница получают динамические импорты с Suspense. Вход, восстановление сессии, права и продуктовые контракты сохраняются.
- [Проект офлайн-синхронизации](../offline-sync.md) отделяет действующие D-233/D-401/D-449/D-497/D-499/D-502/D-528 от предложений: локальное хранение своего аккаунта, устойчивая очередь команд, безопасная повторная доставка, конкурирующие изменения и редактор конфликтов. Новые бизнес-правила и wire-контракт этим документом не утверждены.
- D-543: выход закрывает локальные данные во всех вкладках, сохраняя их до нового успешного входа того же сотрудника. D-544: кэш — 30 дней без использования, подтверждённые команды — 30 дней, pending/conflicts и необходимые исходные данные не удаляются автоматически. D-545: пароль входа автоматически открывает случайный ключ аккаунта; для входа без пароля — отдельный случайный ключ, сохранённый пользователем вне приложения. Cookie/passkey не предоставляют секрет для автоматической разблокировки после перезапуска. Правила внесены в нормативные `../specification/authentication.md` и `decisions.md`; «Забыть» остаётся открытым D-282.
- Native IndexedDB/Web Crypto: AES-GCM-256, PBKDF2-SHA256 600 000, случайные salt/IV, AAD и строгие версии; ключ только в памяти. Блокировка выхода независимо в localStorage/IndexedDB, BroadcastChannel и проверки фокуса; engine повторно проверяет блокировку и текущий header в транзакции. Отзыв клиентских прав удаляет содержимое этой первой базы по D-528.
- Форма нового клиента сохраняет черновик только при открытом vault, неизвестный формат не перезаписывает. Перед HTTP сохраняет неизменные commandId/clientId/данные; неподтверждённую отправку повторяют вручную. При отсутствии настроенного vault сохраняется прежнее онлайн-создание с предупреждением об отсутствии локального сохранения. Обучение и существующие карточки не персистятся этой порцией.
- Service worker, запуск без сети, локальный каталог/справочники, автоматическая очередь и редактор конфликтов ещё отсутствуют. Общий receipt/outbox/pull-протокол в `docs/offline-sync.md` остаётся предложением; текущий create-replay возвращает актуальную карточку, а не неизменный receipt.

Прежние диагностические запуски не считаются успехом. C#/MSBuild не менялись.

## Следующее действие

Ближайшая порция реализации — кэш серверных данных по `docs/offline-sync.md`; запуск без сети и серверный признак сброса требуют отдельных законченных интеграций. Завершённая первая порция готова к ручному ревью. Вопрос о широте поиска ФИО остаётся в [активном реестре](../open-questions.md#допустимая-широта-поиска-по-фио-с-опечатками--п1).
