## Замечания

### P2 — Невалидная дата не блокирует сохранение карточки

`web/src/shared/ui/date-time/ui/DateInput.tsx:43`: невалидный ввод ставит локальный `invalid`, но оставляет родителю прежнее значение. `ClientEditorDrawer.tsx:66` не проверяет состояние даты; `submit()` на строке 175 отправляет прежнее `draft.birthdate`.

Сценарий по обработчикам: открыть карточку с датой, ввести `31.11.2026`, нажать «Сохранить». Blur показывает ошибку, но отправка может сохранить старую дату; при создании — null. Видимый ввод расходится с сохраняемым значением. Браузерное воспроизведение не выполнялось.

Рекомендация: включить ошибочный/незавершённый ввод в валидацию формы и блокировать отправку. Проверить повторное использование Ant Design Form/DatePicker. [DatePicker](https://ant.design/components/date-picker/) поддерживает ручной ввод, форматы, диапазоны и настройку панели. Эквивалентность текущему контракту здесь не доказана: сохранить ISO/wall-clock без timezone, московское «Сегодня», bounds, фокус и мобильное поведение. Замена календаря не должна быть механической.

### P2 — Необъявленный токен убирает границы секций

`web/src/pages/clients/ui/clients.css:155,172,190,210` и `web/src/features/employee-training/ui/clientDirectoryTraining.css:6` используют `var(--color-border)` без fallback. Объявления в исходниках нет; существующий токен — `--color-line` в `app/styles.css`.

Border-декларации не получают допустимого значения; теряются границы контактов, заметок, истории и учебной карточки в обеих темах. Использовать действующий семантический токен, проверить обе темы.

### P2 — Редактор повторяет поведение Form с пробелами в доступности

`web/src/features/edit-client/ui/ClientEditorDrawer.tsx:175,221,251`: отправка через `Button.onClick`, поля в `fieldset` без `form`. Общий Alert не связан с ошибочными полями; отсутствуют их `aria-invalid` и перевод фокуса. Enter в обычном поле не отправляет форму.

Рекомендация: использовать установленный Ant Design Form с управляемым draft либо полноценную семантику HTML form. Сохранить защиту draft/expectedState при фоновых обновлениях. Это возможность переиспользовать foundation, не основание переписывать состояние всего приложения.

### P3 — Тема применяется после React commit

`web/src/app/App.tsx:20` устанавливает `data-appearance` в effect. В `web/index.html` нет ранней инициализации, CSS по умолчанию светлый. При сохранённой тёмной теме до effect custom UI использует светлые токены, хотя ConfigProvider уже выбирает тёмный алгоритм. Есть риск первого светлого кадра; фактическая вспышка не измерялась.

Рекомендация: синхронно задать тему до первого отображения с обработкой недоступного storage. Каталожный выбор — [next-themes](https://github.com/pacocoursey/next-themes), но добавление зависимости ради небольшого bootstrap в Vite SPA не обязательно.

## Что уже соответствует skills

- Одна foundation, собственная бумажная тема и общий Icon на Tabler; фирменный SVG остаётся брендом.
- Библиотечные Modal/Drawer/Dropdown/Select вместо собственных сложных overlay.
- Переиспользуемые DateInput/CollectionDataView без универсальной обёртки над Ant Design.
- Есть loading/empty/error состояния, accessible names, календарная keyboard navigation, responsive CSS и reduced-motion правило. Наличие кода не доказывает полную доступность.
- [Механизм темы Ant Design](https://ant.design/docs/react/customize-theme/) применяется по назначению. Палитра продублирована в TS/CSS: единый источник общих токенов снизит риск расхождения, но это улучшение сопровождения, не отдельный дефект.

## Проверки и ограничения

Прочитаны manifests/lockfile, инструкции, тема, shell, страницы и общие UI, редактор, регистрация, обучение, существующие unit/browser сценарии. Сверена официальная документация Ant Design и next-themes. Тесты, сборка, линтеры, форматтеры, браузер и установка пакетов не запускались; реальные данные не использовались. Старые отчёты не считаются проверкой аудита.

Не подтверждены визуально: контраст, длинный контент, реальные мобильные клавиатуры, screen reader, Tab между портальными popup/Drawer, reduced motion библиотечных компонентов. Эти сценарии нужны для принятия будущих исправлений. Frontend pipeline требует отдельного разрешения по локальным правилам.

Предлагаемый порядок: блокировка сохранения невалидной даты → токен границ → семантика/ошибки формы → ранняя тема. Изменения реализации, зависимости и commit/push в аудит не входят.
