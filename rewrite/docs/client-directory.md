# Список клиентов

Основание — согласованный список по перенесённым данным с уточнением компактного табличного представления. Поля карточки и контактов — CLI-011–CLI-021/D-418, единый архив — D-537, эффективные права — D-519, обучение — D-513/D-538. Исторический референс — текущая **неразвёрнутая** версия `MelodyTrack.Web/src/pages/clients` и `MelodyTrack.Backend/Api/Clients/Endpoints/GetClientsEndpoint.cs`, а не production.

## Доступные данные

Постоянные колонки: ФИО, статус, последняя запись, следующая запись, баланс, быстрые действия. Активный статус пустой, архив обозначен меткой. Занятия и платежи не перенесены: по решению пользователя их перенос остаётся отдельной задачей, а недостающие значения показаны прочерками. После подключения данных последняя запись означает последнее занятие с присутствием клиента, включая консультации; баланс — общую сумму с детализацией по услугам при наведении, зелёным положительным и красным отрицательным значением.

Нажатие на строку или ФИО открывает панель справа: контакты с видами и комментариями, источник, дата рождения, дата создания, ФИО и архив. Исторически отсутствующий источник и пустые контакты допустимы. Ссылки, кнопки и выделение текста не перехватываются обработчиком строки. Быстрые действия открывают карточку, звонок и письмо при наличии контакта. Редактирование, архивирование и финансовые команды не имитируются.

`GET /api/clients` сравнивает ФИО целиком в порядке «фамилия имя отчество»: регистр и повторяющиеся пробелы нормализуются, PostgreSQL `public.levenshtein_less_equal` допускает расстояние до 3. Поиск по отдельным словам ФИО не подменяет это сравнение. Значения контактов ищутся отдельно; телефон можно искать без форматирования (от трёх цифр). Фильтры: архив и источник/его отсутствие. Контактные и календарные фильтры удалены из API и интерфейса. Timestamps передаются в UTC и отображаются по Москве; дата рождения остаётся календарной датой без смещения.

Миграция `0015_EnableClientNameSimilarity.sql` устанавливает расширение в `public`; роль Init должна иметь право его установки. Ограничение Levenshtein в 255 символов проверяется без обрезания имён. Официальный контракт: [PostgreSQL fuzzystrmatch](https://www.postgresql.org/docs/current/fuzzystrmatch.html#FUZZYSTRMATCH-LEVENSHTEIN).

Мультисортировка: `sort=name:asc,status:desc`; сервер поддерживает `name`, `status`, `createdAt`, `birthdate`, `source`. Повторяющиеся/неизвестные поля и направления отклоняются. Стрелка заголовка добавляет поле, переключает asc → desc → выключено, сохраняя остальные приоритеты. Пропущенный sort означает name:asc, явно пустой — стабильный порядок ID. Сравнение идёт по выбранным полям, затем ID; отсутствующие даты/источники всегда внизу. Для неперенесённых колонок сортировки нет. Пагинация после фильтров: по умолчанию 10, в UI 10/20/50/100. Параметры проверяются сервером, текст запроса не включается в ошибки. `GET /api/clients/options` возвращает справочники.

Чтение требует актуального `ClientsRead`, области `Available` и времени `Any`; ограниченные гранты отклоняются с 403. Область собственных клиентов нельзя реализовать достоверно до появления связей расписания. Отказ не маскируется пустым списком и не расширяет доступ до всех клиентов. Все ответы чтения имеют `Cache-Control: no-store`, заметки и финансы не читаются.

SQL сначала отбирает структурные условия в согласованном read-only снимке. Поиск защищённых контактов расшифровывает контакты только отобранных кандидатов и применяется до подсчёта и пагинации. Без поиска расшифровываются только контакты текущей страницы. Текущая реализация читает метаданные всех кандидатов и сортирует их в памяти; это ограничение производительности первого блока, без скрытого обрезания результата и без заявления о готовности поиска для неограниченного объёма. Индекс поиска по шифротексту не создаётся.

## Представление и обучение

Общий `shared/ui/data-view` управляемый: он не сортирует локально уже полученную страницу. Представление — компактная таблица с горизонтальной прокруткой на телефоне, мультисортировкой, серверной пагинацией и отдельными состояниями загрузки, ошибки, повтора и отсутствия результатов. Настроек вида, скрытия/перестановки колонок и карточного режима нет. Поисковый текст, фильтры и строки клиентов не сохраняются в Web Storage и не попадают в адрес страницы.

Раздел «Обучение» и кнопка «Помощь» списка открывают статью и упражнение на вымышленных данных. Зачёт требует верных поиска, фильтров, порядка и результата; чтение статьи само по себе не завершает упражнение. Прогресс прежнего модуля входа сохраняется. Учебный список не обращается к API клиентов.

## Проверки

Для текущей порции выполнен полный `npm run verify:fix`: Biome, TypeScript, 126 тестов в 22 файлах и production-сборка. Итоговая C#-сборка прошла без предупреждений и ошибок. Первый полный backend-запуск: 756 успешных тестов, 245 ошибок общей PostgreSQL-фикстуры из-за недоступности Docker veth после обновления модуля. После перезагрузки пользователь самостоятельно повторил тесты и сообщил об успешном результате; артефакты этого повтора агентом не проверялись. Браузерная приёмка не выполнялась.

Миграция `0015` применена через Init к существующей хостовой базе без импорта и создания пользователей. HTTP-диагностика без авторизации подтвердила 401 вместо 404 напрямую и через Vite-прокси, без чтения карточек. Production-сборка предупреждает о chunk размером около 657 КБ до gzip.
