# Клиенты: список и карточка

Основание — согласованный список по перенесённым данным с уточнением компактного табличного представления. Поля карточки и контактов — CLI-011–CLI-021/D-418, единый архив — D-537, эффективные права — D-519, обучение — D-513/D-538. Исторический референс — текущая **неразвёрнутая** версия `MelodyTrack.Web/src/pages/clients` и `MelodyTrack.Backend/Api/Clients/Endpoints/GetClientsEndpoint.cs`, а не production.

## Доступные данные

Постоянные колонки: ФИО, статус, последняя запись, следующая запись, баланс, быстрые действия. Активный статус пустой, архив обозначен меткой. Занятия и платежи не перенесены: по решению пользователя их перенос остаётся отдельной задачей, а недостающие значения показаны прочерками. После подключения данных последняя запись означает последнее занятие с присутствием клиента, включая консультации; баланс — общую сумму с детализацией по услугам при наведении, зелёным положительным и красным отрицательным значением.

Нажатие на строку или ФИО открывает панель справа: контакты с видами и комментариями, источник, дата рождения, дата создания, ФИО и архив. Исторически отсутствующий источник и пустые контакты допустимы при чтении. Ссылки, кнопки и выделение текста не перехватываются обработчиком строки. Визуальные ориентиры боковой панели и компактных действий взяты из неразвёрнутой старой версии `MelodyTrack.Web/src/pages/clients/ui/ClientsPage.tsx` и `widgets/client-history/ui/ClientHistoryDrawer.tsx`; структура адаптируется к возможностям rewrite. Финансовые и календарные команды остаются отдельными задачами.

## Карточка и изменения

Создание, редактирование карточки и контактов, заметки с историей и восстановление из архива следуют [требованиям клиентов](../../specification/clients.md). Создание требует фамилию, имя и источник; сохранение формы исторической карточки без источника также требует выбрать его. Справочники используются для выбора: их редакторы не входят в эту порцию. Полное удаление клиента отсутствует.

Архивирование для всех карточек заблокировано по [D-541](../../specification/clients.md#граница-архивирования-в-rewrite--d-541), пока не подключены проверки расписания, серий и финансовых зависимостей. Разархивирование сохраняет отзыв прежнего клиентского доступа. Сравнение контактов и предупреждения о совпадениях следуют [D-540](../../specification/clients.md#нормализация-ввода--d-412d-540); исходное представление сохраняется.

| Маршрут | Контракт |
| --- | --- |
| `GET /api/clients/{clientId}` | Профиль, контакты и архив; служебные заметки запрашиваются отдельно |
| `POST /api/clients` | `commandId`, `clientId`, поля профиля и `contacts`; ответ 201 с карточкой и `hasDuplicateContacts` |
| `PUT /api/clients/{clientId}` | `commandId`, исходное `expectedState`, новые поля профиля и `contacts`; конфликт исходного состояния — 409 |
| `GET /api/clients/{clientId}/notes` | Текущее поле `notes` с отдельным правом чтения заметок |
| `GET /api/clients/{clientId}/notes/history` | `items` с автором, временем и защищёнными значениями до/после |
| `PUT /api/clients/{clientId}/notes` | `commandId`, `notes`, `expectedState: {notes}`; 204 при сохранении |
| `POST /api/clients/{clientId}/restore` | `commandId`; 204 при восстановлении |
| `POST /api/clients/{clientId}/archive` | Всегда 409 после проверки права изменения по D-541 |

Изменения используют эффективное `ClientsWrite`, заметки — отдельные `ClientNotesRead`/`ClientNotesWrite`. Команды повторно проверяют актуальные права внутри транзакции; ключ повторной отправки связан с автором, карточкой и содержимым запроса. Конфликт не возвращает чужие значения. Миграция `0016_CreateClientCardCommands.sql` добавляет защищённые отпечатки команд. Восстановление меняет архивный признак, не активируя прежние ссылки и сессии.

## Список и поиск

`GET /api/clients` ищет любую часть ФИО в порядке «фамилия имя отчество» с расстоянием Левенштейна до 3: допускаются вставки, удаления и замены символов как для фрагмента, так и для полного ФИО. Регистр и повторяющиеся пробелы нормализуются. Например, «багд» находит «Богданова Полина». Допуск не уменьшается для коротких запросов: запросы до трёх символов совпадают с любым непустым ФИО. Символы `%` и `_` не считаются шаблонами, но участвуют в сравнении с тем же допуском. Значения контактов ищутся отдельно; телефон можно искать без форматирования (от трёх цифр). Фильтры: архив и источник/его отсутствие. Контактные и календарные фильтры удалены из API и интерфейса. Timestamps передаются в UTC и отображаются по Москве; дата рождения остаётся календарной датой без смещения.

Миграция `0017_AddClientNameFragmentSearch.sql` добавляет `public.client_name_fragment_matches`: сравнение выполняется в PostgreSQL динамическим программированием по Unicode-символам, без ограничения расширения `fuzzystrmatch` в 255 символов и без обрезания ФИО. Существующий шаг `0015_EnableClientNameSimilarity.sql` остаётся неизменным. Новая миграция не преобразует карточки, контакты и историю; перед запуском обновлённого API требуется обычный Init.

Мультисортировка: `sort=name:asc,status:desc`; сервер поддерживает `name`, `status`, `createdAt`, `birthdate`, `source`. Повторяющиеся/неизвестные поля и направления отклоняются. Иконка Tabler в заголовке добавляет поле, переключает asc → desc → выключено, сохраняя остальные приоритеты. Пропущенный sort означает name:asc, явно пустой — стабильный порядок ID. Сравнение идёт по выбранным полям, затем ID; отсутствующие даты/источники всегда внизу. У последней и следующей записи показаны отключённые кнопки сортировки с пояснением: данные о записях ещё не подключены. Они не меняют запрос сервера. Пагинация после фильтров: по умолчанию 10, в UI 10/20/50/100. Параметры проверяются сервером, текст запроса не включается в ошибки. `GET /api/clients/options` возвращает справочники.

Чтение списка и карточки требует актуального `ClientsRead`, области `Available` и времени `Any`; ограниченные гранты отклоняются с 403. Область собственных клиентов нельзя реализовать достоверно до появления связей расписания. Отказ не маскируется пустым списком и не расширяет доступ до всех клиентов. Ответы чтения имеют `Cache-Control: no-store`; список не читает заметки и финансы.

SQL сначала отбирает структурные условия в согласованном read-only снимке. Поиск защищённых контактов расшифровывает контакты только отобранных кандидатов и применяется до подсчёта и пагинации. Без поиска расшифровываются только контакты текущей страницы. Текущая реализация читает метаданные всех кандидатов и сортирует их в памяти; это ограничение производительности первого блока, без скрытого обрезания результата и без заявления о готовности поиска для неограниченного объёма. Индекс поиска по шифротексту не создаётся.

## Представление и обучение

Общий `shared/ui/data-view` управляемый: он не сортирует локально уже полученную страницу. Представление — компактная таблица с горизонтальной прокруткой на телефоне, мультисортировкой, серверной пагинацией и отдельными состояниями загрузки, ошибки, повтора и отсутствия результатов. Настроек вида, скрытия/перестановки колонок и карточного режима нет. Поисковый текст, фильтры и строки клиентов не сохраняются в Web Storage и не попадают в адрес страницы.

Фильтр и поле состояния называются «Статус». В панели действия изменения, архива и восстановления показаны иконками с подсказками и доступными именами; между ними есть отступы. История заметок по умолчанию скрыта и раскрывается отдельной кнопкой возле поля. Обязательные поля отмечены неакцентной звёздочкой, необязательные не имеют дополнительных пометок. Дата рождения редактируется общим `DateInput` с календарём, без системного date picker.

Раздел «Обучение» и кнопка «Помощь» списка открывают статью и упражнения на вымышленных данных. Кроме поиска, фильтров и порядка, упражнение карточки знакомит с обязательным источником и основным контактом; статья объясняет заметки и предупреждение о совпадениях. Чтение статьи само по себе не завершает упражнение. Прогресс прежнего модуля входа сохраняется. Учебные изменения не обращаются к API клиентов.

Полный backend scope `all` прошёл: 1048/1048 тестов, без пропусков и ошибок, итоговая сборка всей rewrite solution без предупреждений и ошибок. Отчёт: `.artifacts/agent-checks/20261115T191002-6d2ca9c9/report.json`. `npm run api:generate` также успешно собрал всю solution и обновил Kiota.

Полный frontend `npm run verify:fix` после UI-правок прошёл: Biome, TypeScript, 185/185 тестов в 29 файлах и production-сборка. Мутации форматтера просмотрены. Отчёт: `.artifacts/agent-checks/20261115T193322-6d3b8cc3/report.json`. Сборка сохраняет предупреждение о крупном chunk; Node также выводит диагностическое сообщение о каталоге доверенных сертификатов окружения, не мешающее локальным проверкам и сборке.

Chromium: 11/11 сценариев, без пропусков и ошибок; `.artifacts/agent-checks/20261115T193344-f50d74fd/report.json`. Мобильный сценарий проверяет загрузку карточки, контактные действия и заблокированное архивирование. Firefox, WebKit и WebKit mobile не запускались; реальный импорт и существующая база в эти проверки не входят.

Миграция `0015` ранее применена через Init к существующей хостовой базе без импорта и создания пользователей. Новая миграция `0016` проверена только на изолированной тестовой базе; к существующей базе в рамках этой порции не применялась.
