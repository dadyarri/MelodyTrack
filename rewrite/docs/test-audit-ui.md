# Аудит UI- и model-тестов rewrite

Область: все тестовые файлы для каталога клиентов, клиентской модели, обучения сотрудников,
общего DataView, выбора даты/времени и границ прокрутки. Ожидания сверены с
[`docs/client-directory.md`](client-directory.md), `web/src/features/employee-training/README.md`,
`web/src/shared/ui/date-time/README.md`, а также D-418/D-519/D-537/D-538 и
`specification/employee-training.md`. Реализация и тесты использованы как описание фактических
сценариев, не как источник бизнес-правила.

## Качество assertions и изоляция

- Тесты каталога проверяют видимые строки, URL и безопасное состояние после гонки/ошибки, а не только вызов приватного callback. Старый response намеренно завершается, пока новый всё ещё загружается.
- Учебное завершение проходит через пользовательские контролы; отдельно читаются сохранённое значение, неизменность старого прогресса и отсутствие сетевого fetch. Модельное ожидание опирается на D-538 и `employee-training.md`.
- Фикстуры контактов синтетические, тесты не сохраняют их в browser storage. Аккаунты и deferred promises изолируются сценариями; компонентные тесты очищают DOM и подменённые globals.
- Изменения моей тестовой пачки ограничены тестами. В общем diff также есть продуктовая правка календаря координатора, отмеченная выше.

## Остаточные пробелы

1. Реальное IndexedDB поведение проверяется отдельными браузерными сценариями: cross-tab stale merge, владение аккаунтом, reload, pre-abort и ошибки транзакции/quota. DOM-тесты обучения отдельно проверяют UI реакцию на отказ save и позднюю загрузку прежнего аккаунта.
2. Синтетический `fetch` подтверждает сериализацию Kiota и поведение страницы до HTTP boundary, но не заменяет API/Init интеграцию; backend payload, SQL фильтры, права, пагинация и отмена проверяются серверными тестами.
3. Browser acceptance покрывает мобильную карточку клиента, календарь и возврат фокуса, а также настоящее wheel scrolling. Screen reader announcements и реальные мобильные клавиатуры остаются отдельной accessibility/device проверкой.
4. Mutation score не измерялся. Сценарии нацелены на регрессии query serialization, filter/sort/page wiring, позднего ответа, сохранения/отсрочки прогресса, владения аккаунтом и клавиатурных границ календаря.
