# Соответствие бэкенда rewrite спецификации

## Область и доказательства

Сопоставлены существующие модели и правила Domain, операции Application, API, клиентское хранилище и импорт Init с [актуальными требованиями](../../specification/README.md), включая D-420–D-528. Финансы, расписание/задачи и доступ/коммуникации/практика дополнительно прочитаны независимыми агентами. Старое приложение не использовалось как источник новых требований.

Основа аудита — ручное чтение исходников и тестовых сценариев. Выполненные проверки контура авторизации и их точный объём приведены ниже; они не доказывают готовность остальных подсистем. Импорт и доступ к реальным данным не выполнялись. Отсутствие замечания не доказывает полноту или работоспособность подсистемы. Инфраструктурные библиотеки не проходили отдельный исчерпывающий аудит отказов и конкурентного исполнения.

В [Program.cs](../src/MelodyTrack.Rewrite.Api/Program.cs) подключены HTTP-команды изменения заметок и создания/исправления расходов с актуальной авторизацией из БД и SQL-транзакцией; исправления требуют ожидаемого исходного состояния. Общий authentication handler проверяет токен сотрудника по D-529, политики маршрутов проверяют актуальную матрицу до чтения тела команды. Без действующего токена команды возвращают 401. Доверенное создание аккаунтов, вход по паролю/passkey, второй фактор и refresh ещё отсутствуют. Большинство остальных операций остаётся в памяти. Ошибка чистого правила ниже не означает, что соответствующий endpoint существует или доступен в production.

P1 обозначает нарушение утверждённого предметного результата при использовании существующей операции; P2 — более узкий дефект либо отсутствующую часть контракта. Приоритет не является оценкой production-инцидента.

Продуктовая приёмка и сквозная готовность всех функций этим не подтверждены. Линтеры, миграции реальной БД и импорт не запускались. Дополнительная граница D-527: `ServiceRules.Archive` получает snapshots платежей/списаний и запрещает архив при неиспользованных оплаченных занятиях этой услуги. Неизвестная историческая привязка не преобразуется молча; SQL-команды архива услуг пока нет.

HTTP-политика проверяет наличие действия; области данных/времени проверяются в Application с фактами команды, а изменяемые предметные права повторно проверяются SQL-транзакцией. ### Проверенный блок авторизации

Добавлены [HTTP-маршруты идентичности и политик](backend-api-contract-proposal.md#идентичность-и-политики-сотрудников). Authentication handler получает сотрудника и сессию одним allowlist-запросом, сохраняет ID сессии только в серверном ticket и передаёт его request-scoped `CurrentStaff`. Logout отзывает только эту сессию, без выбора цели через тело. Существующие заметки и расходы используют тот же контур. Политики роли и личные исключения сохраняют SQL-проверку супера, историю и постоянные ключи команд. Новая миграция не нужна: связь токена с сессией уже есть в `0010`.

Итоговая сборка `20261109T183415-20c287c5`: вся `MelodyTrack.Rewrite.slnx`, exit 0, ноль предупреждений и ошибок. Набор `20261109T183541-286c3cdb`: 123/123 успешных, без пропусков — 15 Domain/Application (`StaffAccessTokensTests`, `StaffPermissionsTests`), все 66 API и 42 PostgreSQL (`StaffAccessTokenStoreTests`, `StaffPolicyStoreTests`, `ClientNotesStoreTests`, `ExpenseStoreTests`). PostgreSQL проверен через изолированные Testcontainers; это не запуск на реальных данных. Проверены выход с сохранением других устройств/аккаунтов, свежая матрица, ранние 401/403, отзыв, наследование/запрет, immutable super, SQL-проверка после смены роли автора, replay и rollback. Это выбранный набор, а не все Domain/Init-тесты.

### Независимое ревью пачки

Перед фиксацией накопленных изменений выполнен полный `all` — `20261109T184832-2e671137`: сборка без предупреждений/ошибок, 764/764 теста успешны, без пропусков. Исправлены два устаревших теста: ожидание отказа при оплате старого долга заменено проверкой согласованного погашения, а тест сохранения метаданных клиента больше не меняет заметки через `UpdateProfile` в обход отдельной истории. Реальная БД и live import не запускались.

Ревьюер прочитал исходники, SQL `0003`–`0006` и сценарии. Исправлены и повторно перечитаны три замечания: неподтверждённое удаление расхода администратором, порядок расходов от старых к новым и потеря нового забытого результата в уже открытой дневной задаче. Для последнего добавлены сценарии прямого обновления и `Ensure`, включая сохранение откладывания. После повторного чтения исправлений существенных замечаний не осталось.

Это заключение ручного ревью, не результат исполнения и не подтверждение полного устранения аудита. Исходные посторонние изменения solution, импорта и спецификации в ревью этой реализации не включались.

## Сохранённые границы и открытые зависимости

- В проверенной практике доступ к чужой свободной истории сравнивается по личности без обхода для супера; копирование/видео и исключение пауз соответствуют D-364/D-366/D-370/D-371. Это ручное сопоставление, без выполнения.
- Клиентские фабрики допускают отсутствие контактов, сохраняют один основной на представленный вид и требуют явного выбора замены. Restore сохраняет исходные значения и допускает неизвестный источник отдельно от новых карточек. SQL содержит ограничения контактов; импорт читает источник в read-only snapshot, сохраняет соответствия UUIDv7 и выдаёт обезличенные проблемы вместо молчаливого исправления. Реальная полнота переноса всех предметных блоков не реализована и не проверялась.
- Курсы/ДЗ отложены D-446. Их типы и тесты не означают готовность или разрешение возвращать механизм в текущую реализацию. Исторические данные сохраняются.
- [BIZ-47](open-questions.md) о скидке на старый долг ожидает заказчика. BIZ-45 не требует нового ответа для количественной оплаты; искусственный неполный резерв не вводится. Возврат в резерв услуги по старой цене, запрет редактирования использованного платежа, прекращение обращения только после проведённого обычного занятия и запрет архива услуги с остатком установлены D-520/D-521/D-526/D-527.
- Группы прав/области и очистка локальных данных определены D-519/D-528. Оставшиеся ролевые проверки и отсутствие клиентской очистки — незавершённая реализация.
- Закрытие рабочей формы запускает пропущенное обучение D-524; изменённая незавершённая часть начинается заново D-525. Явная отсрочка продолжает подавлять автоматический запуск.
