# Серверный контракт

Статус: **принят**, D-519. Определяет группы действий, области прав и первые HTTP-команды BA-008/BA-022. Принятие контракта не означает готовность его реализации. Текущее состояние кода — [в аудите](backend-consistency-audit.md#текущее-состояние-исправлений).

## Команды и права

Не считать каждый endpoint отдельным разрешением. Установлены предметные действия и области ниже; личные разрешения и запреты накладываются на базу роли. Технические идентификаторы конечного набора действий следуют этой группировке. Ограничения давности, истории и предметных состояний остаются обязательными независимо от разрешения. Изменение политик супера и управление God Mode не становятся обычными разрешениями.

| Группа действий | Области | Предметные команды |
| --- | --- | --- |
| Чтение клиентов; изменение карточки | Все доступные клиенты | Карточка, контакты, архив/восстановление с отдельным финансовым закрытием |
| Чтение заметок; изменение заметок | Все доступные клиенты | Текущее поле и защищённая история; изменение с автором/временем |
| Чтение расписания; планирование | Своё / все доступные | Встреча/серия, перенос, замена преподавателя, помещение, отмена |
| Результаты занятий | Все доступные | Отметка и снятие с комментарием для прошлого; финансовый эффект в той же транзакции |
| Отсутствия клиентов; собственные заявки; одобрение отсутствий и графиков | Клиенты / свой сотрудник / другие сотрудники | Раздельные действия; обычное разрешение конфликтов до одобрения |
| Чтение финансов; запись платежа; исправление платежа | Свой клиентский кабинет / все доступные; сегодня / без давности | Дата и комментарий по D-424, оплаченный резерв по услуге |
| Возврат остатка; полный возврат | Все доступные клиенты | Самостоятельный возврат и архив с явно выбранным режимом |
| Чтение расходов; запись/исправление расходов; удаление; экспорт | Сегодня / без давности | Отдельный экспорт; удаление администратора не разрешать без подтверждения |
| Общие задачи | Чтение / обработка / управление правилами | Завершение, откладывание, возврат проблемной задачи; правила и шаблоны отдельно |
| Справочники; сотрудники; политики | Соответствующий раздел | Управление без расширения специальных границ D-498/D-500 |
| Обучение сотрудника | Только собственный прогресс и доступные материалы | Статья, упражнение, демонстрационное состояние, отсрочка |

Глобальная роль задаёт базу, личная правка по действию/области имеет приоритет D-447. Начальные роли и установленные исключения сохраняются. Конкретизация областей в коде следует этой таблице; нельзя расширять согласованную область или обходить предметные ограничения.

## Первые HTTP-сценарии

### Идентичность и политики сотрудников

Технические маршруты реализуют [правила входа и выхода](../../specification/authentication.md) AUTH-027/D-281/D-529 и [матрицу доступа](../../specification/access.md) D-420/D-447/D-495/D-498. Они используют общий Bearer handler и актуальную серверную идентичность.

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| `GET /api/auth/me` | Без тела | `200 { staffId, role, permissions: [{ permission, allowed, dataScope, timeScope }] }`, `Cache-Control: no-store` |
| `POST /api/auth/logout` | Без тела; цель определяется предъявленным токеном | `204`; все токены текущей сессии теряют доступ, другие сессии сохраняются |
| `PUT /api/access/roles/{role}/permissions/{permission}` | `{ commandId, grant: { allowed, dataScope, timeScope } }` | `204`; актуальное право супера повторно проверяется SQL-транзакцией |
| `PUT /api/access/staff/{staffId}/permissions/{permission}` | `{ commandId, grant }`, явный `null` восстанавливает наследование | `204`; актуальное право супера повторно проверяется SQL-транзакцией |

Названия ролей, действий и областей передаются строками в camelCase; числовые enum-значения не принимаются. `grant` обязан присутствовать, `allowed` внутри ненулевого `grant` также обязателен. У роли `grant: null` недопустим. `/me` возвращает только собственную роль и эффективные настройки действий/областей: это не разрешение обходить предметные ограничения. Ответ не раскрывает секрет токена, хеш и идентификатор сессии. Невалидный токен даёт `401`, отсутствие права — `403` до разбора тела команды; остальные ошибки — `400`, `404`, `409` по причине отказа. Logout не удаляет запомненную браузерную запись. Публичная выдача токена, пароль/passkey, 2FA, refresh и чтение полной матрицы для редактора в эту реализацию не входят.

### Предметные команды

Принятые пути и формы первых команд:

| Метод и путь | Поля команды | Транзакционный результат |
| --- | --- | --- |
| `PUT /api/clients/{clientId}/notes` | `commandId`, `notes`, ожидаемое исходное состояние | Текущие заметки + защищённая история + безопасный маркер общего аудита |
| `POST /api/clients/{clientId}/payments` | `commandId`, `serviceId`, `quantity`, `paidAt`, `discountActivationId?`, `comment?` | Платёж с зафиксированными условиями, аудит и требуемая актуализация долга |
| `PUT /api/appointments/{appointmentId}/result` | `commandId`, `status`, `comment?` | Состояние + списание + предметная история + аудит/последующая работа |
| `DELETE /api/appointments/{appointmentId}/result` | `commandId`, `comment?` | Снятие результата с сохранением исходных фактов и возвратом в резерв той же услуги по старой цене |
| `POST /api/expenses` | `commandId`, `description`, `amount`, `date`, `categoryId?` | Факт + предметная история + типизированный аудит |
| `PUT /api/expenses/{expenseId}` | Те же поля, `comment?` и ожидаемое исходное состояние | Адресное сравнение и атомарное исправление |
| `POST /api/work-items/{workItemId}/reopen` | `commandId` | Текущее основание вычисляет сервер; проблемное состояние не теряется |
| `POST /api/training/{scenarioId}/commands` | `commandId`, `expectedRevision`, предметное действие | Только персональный прогресс и демонстрационное состояние |

Автор и его права не принимаются из тела команды. Токен задаёт идентичность; текущий пользователь, политика и личные исключения читаются на сервере. Постоянный ключ повтора привязывается к владельцу и смыслу команды; повтор не исполняет изменение второй раз и не перезаписывает более новое состояние. Клиент не присылает вычисленные баланс, списание, роль или результат проверки права.

Финансовые границы команд: новая оплата количества погашает старые занятия этой услуги и оставляет неиспользованное количество; применение скидки к старому долгу ожидает заказчика в BIZ-47. Снятие результата возвращает оплату в резерв той же услуги по старой цене D-520. Хотя бы частично использованный платёж нельзя редактировать D-521. Неполный денежный резерв не вводится для новых платежей без реального основания; денежное распределение полной оплаченной суммы является инженерной детализацией и сохраняет количество занятий и общую сумму. Редкие повторные закрытия BIZ-48 не требуют отдельной подсистемы и не получают выдуманных финансовых правил. Промокоды сравниваются без учёта регистра D-522. Реализация контракта ещё не завершена.

При обнаружении отзыва доступа во время синхронизации локально накопленные данные удаляются, как только это возможно D-528. Очистка не разрешает неавторизованные команды и не меняет правила уже зафиксированных серверных конфликтов D-499/D-502. Конкретный протокол credential flows, доставки и офлайн-конфликтов остаётся отдельной частью проектирования; эти пути не объявляют его готовым.
