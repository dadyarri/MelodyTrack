# Rewrite frontend

Эти инструкции дополняют `../AGENTS.md`. Требования — в `../../specification/`; состояние текущей порции и запуск — в `README.md`.

- React/TypeScript и Vite; интерактивные примитивы — Base UI по D-565 в `../../specification/architecture.md`. Использовать существующие CSS-токены и компоненты `shared/ui/paper`; не создавать универсальную обёртку над всей библиотекой.
- Слои: `app → pages → widgets → features → entities → shared`. Соседние slices не импортируют друг друга; композиция располагается выше.
- Использовать только контракты rewrite. Старые API, Kiota-модели и правила хранения браузера не определяют контракт новой версии.
- Запросы выполнять через Kiota-клиент из `src/shared/api/generated/`; генерация — `npm run api:generate` в elevated shell. Не писать параллельный HTTP-клиент или вручную редактировать generated файлы. Транспортные настройки и безопасные ошибки находятся в Kiota adapter; generated код исключён из форматирования, но включён в TypeScript.
- Сохранять минималистичную бумажную тему исходного приложения. Короткие подписи и действия в рабочем UI; подробные объяснения — в инструкции или обучении.
- Стили кастомных компонентов хранить в CSS Modules рядом с компонентами. Глобальный CSS оставлять для токенов темы и базовых стилей документа.
- Не сохранять пароли, одноразовые коды, токены или challenge в Web Storage/IndexedDB, URL, логах или диагностических артефактах. Аутентификационный ввод не является durable form.
- Браузерный прогресс и будущие локальные рабочие данные принадлежат конкретному серверному аккаунту, имеют версию и проверяются при чтении. Отказ хранилища и отсутствие серверной синхронизации не выдаются за успешное сохранение на сервере.
- Обучение добавляется вместе с рабочими возможностями D-538. Учебные изменения выполняются только на демонстрационных данных; статья не засчитывает упражнение как пройденное.
- Поддерживать мобильный ввод без zoom-trap, практические touch targets, safe areas, внутреннюю прокрутку полноэкранных форм. WebAuthn вызывается непосредственно из пользовательского события, до асинхронной границы.
- Никаких автоматических проверок между промежуточными правками. После готовой пачки и явного разрешения — `npm run verify:fix` с просмотром его мутаций; браузерные сценарии проверяются отдельно. Не ослаблять правила ради зелёного отчёта.
- Новые тесты колоцируются с кодом: `describe` называет способность, `it` описывает наблюдаемое поведение. Состояние mocks, timers, local storage и аккаунтов изолируется.
- Commit/push/release не следуют из реализации. Не коммитить `.env.local`, ключи, runtime state, `node_modules`, `dist` и браузерные артефакты.
