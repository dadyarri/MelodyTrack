---
name: rewrite-verification
description: Проверять законченную пачку MelodyTrack rewrite и раскрывать сохранённые диагностические отчёты; не запускать проверки между промежуточными правками.
---

Вход: законченный diff и явное разрешение на проверки. Прочитай `../../../AGENTS.md` и раздел CLI в `../../../docs/agent-workflow.md`. Это специализация существующего melodytrack-verify для rewrite, не запуск старых pipelines.
1. Выбери минимальный scope по изменению: domain, api, init, all, build, frontend, browser. `all` включает только backend. `frontend` сохраняет `npm run verify:fix` (просмотри мутации форматтера), `browser` запускает Playwright; выбор `--browser-project` явно ограничивает проверку. Для занятого dev-порта используй `--browser-port`. Для агентной инфраструктуры используй Python unittest и структурную проверку; готовую интеграцию frontend runner проверь его новыми scopes без backend build.
2. Посмотри план `python3 scripts/agent_checks.py plan --scope <scope>`. Для выполнения dotnet-обёртки запроси elevated shell до первой попытки; она может выполнять restore. При отказе останови lane без обходов. Init требует Docker, live import требует отдельного явного разрешения и не входит в обычную проверку.
3. Запусти `run` с выбранным scope. Читай summary, затем details выбранной ошибки, после — полный лог/нативный XML. Не отправляй тысячи успешных тестов в контекст.
4. При исправлении собственной ошибки повтори релевантную проверку. rerun-failed доказывает только subset: не заменяй им исходный полный запуск и не объявляй весь набор зелёным.
5. Отчитайся фактическими командами, scope, status/exit_code, артефактами, пропусками и блокерами. Неизвестный/повреждённый/пустой результат не успех.
Завершение: достаточные проверки прошли или ограничения явно названы. Не запускай release/commit/push из этого skill. Не добавляй TRX extension ради отчёта: используется native xUnit XML.
