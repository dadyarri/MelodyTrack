# Перенос данных и приёмка

Перенос — в отдельную целевую БД, с пробным прогоном и сверкой перед переключением D-397. Исходная база сохраняется. Ни отсутствие новой реализации, ни отказ от сущности не разрешают потерять историю.

## Источник и предварительная сверка

Один production-инстанс PostgreSQL 17; источник — master, commit `1636c2c4dabdd33420209cfd6617cc3c82fe2433` D-413/D-415. Исторический анализ feature/passwordless-portal (`34bc1c7c03afe2a2b64b6a703eb4ef5fad3f2bfa`) не является источником production: эта ветка не разворачивалась.

D-416 закрывает предварительную сверку версии: по подтверждению пользователя старый Init надёжно применил все 49 миграций до `20260904141137_Stage14TimedVacations` включительно. Предоставленные последние 14 идентификаторов и итог 49 строк достаточны; полный журнал и отдельная выгрузка структуры не являются предварительным условием проектирования. Это подтверждение пользователя, не прямое обследование production.

[Исходная схема](../rewrite/docs/source-schema.md) описывает 45 EF-таблиц; [карта переноса](../rewrite/docs/migration-map.md) учитывает каждую. Старые наблюдения о PostgreSQL 16/18 в тестах/фикстурах не меняют цель 17. Пробный перенос, данные на копии и восстановление ещё подлежат приёмке; чтение исходников само по себе не подтверждает перенос.

## Сохранение и преобразование

- Генерируются новые UUIDv7 с устойчивыми соответствиями всех старых ID D-414. Связи в строках, документах, аудите и внешних адресах перепривязываются. Повтор/продолжение одного переноса не создаёт новые соответствия или дубли.
- Непредставимые состояния выдаются предупреждениями для ручного разрешения D-399. Нет молчаливого округления времени, выдуманного преподавателя/источника/причины отмены, фиктивного клиента для контакта или удаления неудобной истории.
- Все исходные покупки абонементов, покрытия, продления и финансовые факты сохраняются. Новые продажи/применения абонементов исключены D-428/D-450. Их историческое представление проектируется отдельно и не требует сохранять вторую постоянную модель оплаты.
- Курсы, программы, прогресс, материалы и ДЗ сохраняются исторически. Новая учебная механика, редакторы, выполнение и напоминания отложены D-446. Приёмка сохранения данных не означает обязательную реализацию обучения сейчас.
- ФИО, Birthdate, источник, CreatedAt и исходные состояния клиента сохраняются. Новая карточка требует фамилию/имя и источник; историческое отсутствие источника не заменяется выдуманным. Клиент без контактов допустим D-418.
- Каждое непустое Phone/Email/Telegram/Vk переносится в отдельный контакт. Виды/значения/комментарии не объединяются по сходству. Одинаковые контакты разных клиентов допустимы; международные номера сохраняются.
- В каждом представленном виде один основной контакт. У единственного перенесённого контакта вида он основной; при последующем удалении основного с оставшимися требуется явный выбор D-119. Пустой список не является ошибкой.
- Закрытые лиды сопоставляются архиву без двух постоянных признаков; будущие записи разбираются без автоматической потери расписания D-102/D-103. Физически удалённые старой системой карточки нельзя объявить восстановленными по коду.
- У каждой исходной встречи сохраняются идентичность, участник, время, цена/финансовое основание, результат и серия по подтверждённым фактам. Сходство дат не доказывает причину отмены или связь с серией. Импорт не создаёт компенсации/уведомления/повторные списания как побочный эффект.
- Нативные PostgreSQL enum и имена Birthdate/birthdate — D-419; исходные числовые значения и имена источника не переименовываются задним числом в инвентаризации.
- Credentials, сессии, разрешения, календарные/push-подписки, задачи и состояния обработки требуют явного соответствия. Нельзя считать их перенесёнными только по совпадению поля или восстановить токен из неполных данных. Технические таблицы Quartz не запускают старые locks/fired triggers в новом scheduler.

## Сценарии приёмки текущего поведения

| Область | Критерий |
| --- | --- |
| Парные встречи | Одна встреча, отдельные результаты и списания. Каждый платит обычную стоимость. Отмена одного не отменяет второго и не освобождает занятые им ресурсы |
| Расписание | Один обязательный преподаватель и необязательное помещение; пересечения запрещены. Длительность из услуги 30/45/60/90/120, по умолчанию 60, созданные встречи/серии сохраняют её |
| Серии | Недельные дни/время, дата/количество/бессрочно. Исходный номер сохраняется при переносе; правка будущей части сохраняет индивидуальные изменения D-385 |
| Материализация | Для бессрочной серии окно 12 месяцев; конфликт не создаёт скрытую встречу, одна задача на серию ведёт к явному разбору D-383–D-389 |
| Отпуска и график | Сначала отмена/перенос/замена преподавателя, затем одобрение. Нет автоматической компенсации/восстановления хвоста при отпуске D-444 |
| Закрытия школы | Отдельные D-270–D-272 сохраняются; исключение новой сущности абонемента отменяет только соответствующие продления |
| Результаты | Отметка ручная после окончания. Будущая встреча не завершается. Забытый результат создаёт задачу без автоматического списания; стоимость прошедшего участия без результата не входит в ожидаемый итог, отмеченное участие второго клиента сохраняется, задача по отсутствующему результату остаётся открытой D-461 |
| Цена и периоды | Цена на окончание, месяц на московское начало. Платежи/расходы относятся к месяцу внесения. Новая цена не вводится в прошлом |
| Деньги | Только пополнение и отдельные занятия; вычисляемый баланс, долг не блокирует запись. Поступления и стоимость занятий в прогнозе не удваиваются |
| Скидки | Вниз до десятков, минимум ноль; конечная граница индивидуального срока исключена. Снятие результата возвращает использование без новой активации |
| Возвраты | Остаток — сотрудники, полная сумма внесённого — супер. Исходные факты сохранены; будущие записи/серии блокируют архив до явного разрешения |
| Политики | Роль задаёт базу, личные исключения сохраняются при её изменении. Токен не удерживает старые права. Статистика доступна администратору, прежние расходы/экспорт — суперу |
| Заметки | Текст и история читаются сотрудниками, клиенту закрыты; общий аудит не получает содержимое заметок |
| Архив | Клиенты/услуги не теряют историю. Будущее расписание блокирует архив. Архив клиента отзывает доступ, разархивирование требует новой ссылки и само не восстанавливает расписание |
| Аккаунты | Переключение не объединяет права, балансы и команды. Отзыв/блокировка действует на всех устройствах даже с ещё действующим access token |
| Вход | Собственные аккаунты сотрудников, пароль/passkey и согласованный фактор. Refresh сотрудника — две недели с продлением; клиентский доступ до отзыва. Восстановление через супер/сервер |
| Задачи | Общая очередь без исполнителя, календарные повторения без автоматического накопления; ручной возврат любого типа сохраняет проблемный конфликт D-437 |
| Мобильность | iPhone 13/13 mini и Android/Chrome, последняя/предыдущая основные версии браузеров; все доступные тренажёры. Видео достаточно на компьютере |
| Офлайн | Полная работа доступных функций, устойчивые команды владельца, синхронизация с проверкой прав/ограничений и редактором конфликтов; курсы/ДЗ не возобновляются |
| История | Количество и согласованные финансовые/учебные факты объяснимо сверяются с источником; предупреждение не считается успешным переносом |

Старые критерии выдачи новых абонементов, компенсации отпусков и немедленной работы ДЗ больше не являются действующей приёмкой. Это будущие проверки, не результаты запусков.

## Переключение и восстановление

По D-465 точные пооперационные списки составляются позже. Их отсутствие сейчас не отменяет D-396 и не является основанием считать готовым переключение; перечень и приёмка нужны до переключения.

D-396 требует повседневные сценарии старой системы с явно согласованными исключениями D-428/D-446; пооперационный перечень ещё фиксируется. Все старые неучебные виды задач обязательны D-417; ДЗ отложено. Пробный перенос, разбор предупреждений, сверка и замеры предшествуют финальному окну. Двойная запись и переход production на месте не выбраны.

Один Linux-сервер, Compose и единый API/frontend-host. Предрелизная проверка локальная, отдельный стенд не требуется. Обновление вне рабочих часов, простой около 5–10 минут D-344.

Ежедневные логические дампы на основном сервере за семь дней, без внешнего места и оповещений D-345–D-347/D-410. При сохранившейся пригодной копии и конфигурации/ключах цели потери данных и восстановления — по суткам. Потеря сервера вместе с копиями этим планом не покрывается. Суточная аварийная потеря не разрешает плановую потерю истории при переносе.

После восстановления обязательного сброса всех доступов нет D-348. Если откат возвращает отозванный доступ, сброс ограничивается затронутыми по сохранившимся сведениям; потерянная информация об отзыве не считается восстановленной самой копией. Регламент и замеры ещё требуется оформить. Значения ключей/секретов в документацию не помещаются.

Схема обновляется только Init; API не выполняет миграции при старте. Выпущенные шаги неизменяемы; порядок, checksum и транзакционная история обязательны. Эта редакционная сверка не запускает перенос, проверки или развёртывание.
