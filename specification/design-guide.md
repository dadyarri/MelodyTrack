- Простота ежедневной работы приоритетна; перегруженные формы текущей системы, не подходящие для модальных окон, нужно перепроектировать D-218. Основные правила размещения форм подтверждены D-219 и описаны ниже.

- Расписание на телефоне — недельная агенда списком с группировкой по дням, как сейчас; дополнительные режимы не нужны D-220. Не добавлять мобильную сетку одного дня или переключатель альтернативных представлений. Детали — [расписание](scheduling.md).
- При активации промокода для клиента сотрудник выбирает одну услугу D-215. Активация доступна суперпользователю и администратору, управление кампаниями — только суперпользователю D-207. Самостоятельный ввод клиентом не предусмотрен D-206. Подробности — [финансы](finances.md).
- **Отложено D-446.** Материалы и задания редактируются кастомным редактором. Файлы по прямым ссылкам показываются оформленными карточками скачивания; YouTube и тренажёры — отдельными виджетами D-171–D-173. Подробности — [редактор и виджеты](documents-and-widgets.md).
- **Отложено D-446.** Курс открывается по освоению всех зависимостей темы, включая зависимости из параллельных веток; закрытая часть покрыта «туманом войны». Материал и ДЗ открываются вместе. Учебный статус и доступность показываются отдельно; детали — [курсы](courses.md), D-137–D-140.
- Повседневный интерфейс должен быть удобен на небольших экранах.
- Целевые устройства включают iPhone 13 и iPhone 13 mini, а также Android в Chrome D-373. Целевые браузеры — последняя и предыдущая основные версии D-372. Все доступные тренажёры работают на телефоне D-453; экспорт видео достаточно на компьютере D-375.
- Интерфейс системы и публичный сайт только на русском языке, без переключения языков D-376.
- Требуется исправить мобильные уведомления и поиск клиента при внесении платежа.
- Абсолютные отметки времени поступают из API в UTC и преобразуются на клиенте в единый Europe/Moscow D-133, D-141, независимо от зоны устройства. Выбор часового пояса не требуется. Даты без времени, например дата рождения, отображаются без смещения часовой зоны.
- В выборе преподавателя занятия показываются имена последних преподавателей этого клиента (D-019); отсутствие истории не отменяет обычный выбор преподавателя.
- При создании серии конфликты показываются до сохранения, пропуск дат выбирается явно (D-024).
- При переносе времени или замене преподавателя в серии доступны две области: «только это занятие» и «это и последующие» (D-028). Значение области объясняется на выбранной дате.
- Сокращение/удаление отпуска не восстанавливает встречи и не заменяет хвост. Нужные изменения выполняются обычными действиями D-444.
- Отмена и сгорание должны ясно различаться: отмена без списания, сгорание со списанием (D-014, D-035).
- Начало занятий выбирается только по целым часам; окончание показывается по длительности услуги и может иметь ненулевые минуты (D-051).
- В расписании преподавателю недоступны действия изменения статуса занятия, включая собственное (D-063). Разрешённое изменение учебного прогресса курса остаётся отдельным действием.
- Отпуска вводятся точными датами/временем без округления до суток D-065. Абонементных карточек/сроков в новой функциональности нет D-428.
- Нужен выбор запомненных клиентских и сотруднических входов. Клиент с действующим сохранённым доступом открывается сразу; общий родительский кабинет не создаётся (D-075–D-077).
- Переключение аккаунта общее для всех вкладок браузера (D-080). При выборе запомненного сотрудника с действующим доступом запрашивается только второй фактор, если он есть; без него аккаунт открывается сразу (D-081). Для администратора и суперпользователя фактор обязателен (D-082).
- Сотрудникам доступны код из аутентификатора или passkey для второго фактора при парольном входе, а также passkey вместо пароля (D-079, D-083). При входе по passkey с обязательным/включённым фактором затем запрашивается код из аутентификатора (D-084).
- У каждого сотрудника собственный аккаунт, включая каждого администратора (D-085). Восстановление доступа — через суперпользователя, а при потере доступа всеми суперпользователями — через серверный «Режим Бога» (D-086); процедура и экраны ещё проектируются.
- При истечении refresh token сотрудника запомненная запись остаётся с предупреждением; для продолжения требуется повторный вход по паролю или passkey с необходимым фактором (D-088, D-093–D-094). Access token действует пять минут и обновляется в фоне; каждое успешное обновление сдвигает двухнедельный срок refresh token вперёд (D-089, D-095). К клиентам двухнедельное ограничение не применяется (D-092).
- Клиентский кабинет остаётся доступным до отзыва без периодического повторного входа (D-096). При замене/отзыве ссылки доступ прекращается на всех устройствах (D-097). Блокировка сотрудника/изменение прав действуют сразу (D-098); состояние интерфейса и его действий должно соответствовать актуальному доступу.
- Клиенты архивируются без полного удаления; отдельное закрытие лида заменено архивом (D-100, D-102). Услуги архивируются, полное удаление доступно только для неиспользованных (D-101). Перед архивированием показываются будущие занятия/действующие серии и требуется их явная отмена/завершение (D-103–D-104); история не мешает архиву.
- Архив клиента автоматически отзывает доступ на всех устройствах (D-105). Клиентов/услуги можно разархивировать без автоматического восстановления расписания (D-106); клиенту нужна новая ссылка, старый доступ не активируется (D-108). Эти последствия объясняются в действиях архива/разархивирования.
- Заметки клиента и историю текста читают все сотрудники D-432; текущее поле редактируют администратор и суперпользователь. Клиенту поле недоступно.
- В новой карточке обязательны фамилия/имя и источник; отчество, дата рождения и заметки необязательны D-113. Контакты могут отсутствовать полностью D-418. Контакты — повторяемые строки «вид / значение / необязательный комментарий», несколько одного вида разрешены (D-111).
- Вид контакта задаёт ввод, маску и проверку через базовый телефон/почту/ссылку; телефон поддерживает международные номера (D-112, D-115). Конкретные маски и нормализация ещё проектируются. Настройка справочника — отдельный экран суперпользователя (D-110, D-114); администратор выбирает виды в рабочей форме.
- У каждого представленного вида один основной контакт; при его удалении требуется явно выбрать новый среди оставшихся (D-116, D-119). Совпадение телефона/email с другой карточкой вызывает предупреждение без блокировки сохранения (D-118). Использованный вид можно архивировать с сохранением контактов и переименовать; изменить базовый формат или полностью удалить его нельзя (D-117, D-120).

## Рабочие разделы — D-235–D-238

Карточка клиента — отдельная страница с краткой шапкой и разделами «Обзор», «Расписание», «Финансы», «Обучение», «История» D-235. Каждый раздел имеет самостоятельные действия редактирования. Видимость соответствует правам: название раздела не разрешает доступ к его содержимому; финансовые права администратора определены D-424/D-425.

Преподавателю доступен раздел «Мои ученики» с клиентами по назначенным ему курсам и переходом к материалам и учебному прогрессу D-236. Финансы ему закрыты; чтение заметок/истории текста открыто сотрудникам D-432. Учебный раздел целиком отложен D-446. Связь определяется назначением на курс клиента, а не историей встреч.

Задачи — обычный список с разделами актуальных, отложенных и истории. Действия «Выполнить», «Отложить», «Отменить» доступны быстро, подробности открываются по необходимости D-237. Очередь общая, настройка шаблонов — отдельная работа суперпользователя. Точные фильтры и поля ещё прорабатываются в [задачах](tasks.md).

Администратор может создать разовую задачу D-240. Произвольного редактора названия, описания, срока и подготовленного текста отдельной открытой задачи нет D-241; действия выполнить, отложить и отменить сохраняются. Обновление общих шаблонов суперпользователем — отдельный сценарий.

В назначенном курсе преподаватель видит всю программу и материалы, клиент — доступное по прогрессу D-242. Обычная смена учебного статуса сохраняется сразу; если откат закроет зависимые темы, до сохранения требуется подтверждение с перечислением последствий D-243. Клиент может иметь несколько разных текущих курсов, но только одно активное прохождение каждого D-244; прошлые прохождения доступны как история.

В календаре суперпользователь по умолчанию видит своё расписание и может выбрать любого преподавателя либо общее. Администратор начинает с общего и может выбрать любого преподавателя. Преподаватель видит только своё, переключателя у него нет D-238. Это выбор отображаемого расписания, не смена аккаунта. Стартовые экраны суперпользователя и администратора остаются дашбордом.

## Формы и контекст работы — D-219

Подтверждены требование простоты D-218 и следующие основные правила D-219. Для календарной формы действует уточнение D-221: привычный календарь сохраняется, контейнер формы выбирается отдельно. Конкретные макеты ещё не утверждены.

| Сценарий | Размещение | Причина |
| --- | --- | --- |
| Клиент с несколькими контактами и связанными данными | Отдельная страница | Достаточно места для полей и переходов к истории, занятиям и курсам |
| Создание/редактирование занятия и серии из календаря | Широкая модалка на компьютере, полноэкранный диалог на телефоне D-222 | Сохраняется привычная работа календаря; новая компоновка даёт место параметрам и последствиям без искусственных пустых областей |
| Редактор курса/материала, шаблон задачи, создание маркетинговой кампании | Отдельная страница | Длинное редактирование, составные настройки или предпросмотр |
| Внесение платежа, смена результата, короткое подтверждение | Короткий диалог на большом экране | Одно действие и небольшой объём ввода |
| Короткая форма на телефоне | Экран целиком | Поля и действия доступны при открытой клавиатуре |

Для календарной формы выбраны широкая модалка на компьютере и полноэкранный диалог на телефоне D-222. Наличие большого экрана само по себе не требует растягивать поля на всю доступную ширину либо заполнять пространство дополнительными сведениями.

Общие правила:

- На экране ясно обозначены текущее действие и основная кнопка сохранения; связанные данные не превращаются в одну общую форму редактирования всего клиента.
- Поля сгруппированы по смыслу. Дополнительные настройки раскрываются по необходимости; ошибки обязательных полей не скрываются в свёрнутых секциях.
- Не превращать каждую форму в пошаговый мастер. Шаги оправданы, только если следующий набор действий зависит от предыдущего выбора.
- Не открывать модальное окно поверх другого. Если при записи нужен новый клиент, переход к его созданию и возврат должны сохранить введённые параметры записи.
- Отдельные страницы должны поддерживать понятный возврат: к выбранной дате календаря либо к исходному списку с его поиском и фильтрами.
- Расположение формы не должно скрывать последствия действия: для серии остаются явные конфликты и область изменения, для платежа — выбранный клиент и сумма.

По D-231 прежнюю систему черновиков пользователь считает переусложнённой. По D-233 принят простой сценарий: один локальный черновик на форму/запись и аккаунт, автоматическое сохранение ввода, восстановление либо удаление при возврате, очистка после успешного сохранения. Для несохранённого черновика формы автоматической отправки нет. Это не очередь уже сохранённых пользователем офлайн-команд D-449; её синхронизация описывается отдельно. Не переносить автоматически прежние статусы, баннеры, сроки хранения и механизм инфраструктуры. Технический способ хранения пока не выбран; полная офлайн-работа с редактором конфликтов выбрана D-449; технический протокол ещё проектируется.

По D-234, D-239 разные пользователи могут работать параллельно, например администратор записывает клиента, преподаватель читает расписание, клиент открывает ДЗ. Совместный онлайн-редактор не нужен. Для конфликтов синхронизации офлайн-команд нужен отдельный редактор D-449. Глобального запрета параллельных входов нет. Правила целостности расписания, финансов и доступа сохраняются; способ защиты обычных команд не требует отдельного интерфейса совместной работы.

Критерий для будущих макетов: на iPhone 13 mini пользователь может заполнить обязательные поля, исправить ошибку, сохранить либо вернуться без потери контекста; большая форма не требует навигации между несколькими прокручиваемыми окнами поверх страницы. Это критерий проектирования, а не выполненная проверка.

### Календарная форма — D-222

Подтверждено D-221: сценарии и привычное представление календаря устраивают пользователя; переработка календаря ради нового контейнера формы не требуется. Это не отменяет согласованные правила отпусков, конфликтов и повторений.

В [существующей форме](../MelodyTrack.Web/src/features/manage-appointment/ui/ScheduleModals.tsx) поля расположены одной вертикальной колонкой: клиент, услуга, преподаватель, тема, заметки, начало, параметры повторения. По D-222 меняются размер контейнера и компоновка содержимого.

Подтверждено D-222; конкретный макет ещё предстоит подготовить:

- На компьютере широкая центральная модалка с ограниченной шириной содержимого. Начальная оценка для макета — около 900–1000 px с адаптацией к окну; это не жёсткий размер для реализации. Высота определяется содержимым и ограничена доступной высотой экрана.
- Основные поля размещаются в двух смысловых колонках при достаточной ширине. Заметки и раскрываемый блок повторения используют общую ширину; нет искусственной пустой колонки, если повторение выключено.
- На телефоне тот же сценарий открывается полноэкранным диалогом: одна колонка, заголовок и действия доступны, содержимое прокручивается с учётом клавиатуры.
- Закрытие возвращает к календарю с прежней неделей, фильтрами и положением прокрутки. Поведение несохранённых изменений ещё требуется детализировать.
- Контейнер не растягивается на весь большой монитор; свободное место не заполняется новыми необязательными блоками только ради плотности.

При обсуждении альтернатив drawer рассматривался для сценария параллельной работы с календарём, а bottom sheet — для коротких мобильных действий. Для этой формы выбран вариант широкой модалки на компьютере и полноэкранного диалога на телефоне D-222.

## Визуальное направление и навигация — D-225–D-228

Сохранить приблизительно текущие цвета D-225. Основа — [действующая палитра](../MelodyTrack.Web/src/app/styles/index.css): тёплые светлые поверхности, коричневый акцент, тёмная палитра с тёплыми оттенками. Точные значения можно корректировать при работе над читаемостью и единообразием; новая палитра с нуля не требуется.

По D-226 клиентский кабинет сохраняет RPG-оформление и получает переключаемую спокойную альтернативу с теми же возможностями. Выбор оформления не меняет правила обучения или отложенный расчёт рейтинга. По D-227 поддерживаются светлая и тёмная темы и режим «как в системе», с ручным выбором. Конкретное сочетание выбора темы и оформления прорабатывается в макетах.

По D-228 на компьютере используется боковое меню, на телефоне — нижняя панель частых разделов и «Ещё». Состав определяется ролью и разрешёнными действиями; точные пункты прорабатывает ассистент. Переключение роли или оформление не даёт дополнительных прав.

Рабочая карта основных разделов для дальнейшего макета, пока не отдельное подтверждённое решение:

Внесение платежа администратором остаётся быстрым действием и действием в контексте клиента; отдельный финансовый отчёт или полный реестр платежей этой картой не разрешается. «Мои курсы» клиента показывает его прохождения, а не самостоятельное назначение программы из каталога. Точное место будущих направлений из roadmap рассматривается по их сценариям, карта не исключает их из продукта.

По D-232 большинство текущих сценариев устраивает заказчика: сохранять привычное поведение, улучшать конкретные проблемные места и согласованные новые возможности. Необходимость переписывания фронтенда не означает необходимость заново изобретать каждый экран. Текущий [portal design system](../MelodyTrack.Web/docs/portal-design-system.md) служит источником оформления и сценариев, но не обязывает переносить прежнюю реализацию компонентов.

## Редактор тем и материалов — отложено D-446

Отдельная страница темы содержит материал, общее ДЗ и предпросмотр отображения для клиента. Изменения применяются по «Сохранить», отдельной стадии публикации нет. Базовые средства — заголовки, текст, жирный/курсив, списки, цитаты, таблицы и ссылки, плюс виджеты файлов, YouTube и тренажёров.

При вставке внешней ссылки предлагается подходящий виджет либо обычная ссылка; название файловой карточки можно изменить. В YouTube можно необязательно задать фрагмент, а позиция из входного `t=100s` учитывается при вставке. Подробности — [редактор и виджеты](documents-and-widgets.md).

Отложено D-446: зависимости темы выбираются из списка, карта строится автоматически. Преподаватели предлагают правки программы, супер применяет D-423; группировка и туман войны остаются отложенными вопросами. Редактор материалов/ДЗ не требуется для текущих форм школы.

## Заявки на отпуск — D-254–D-258

Форма клиента: точные начало и окончание, необязательный комментарий. Пока заявка не рассмотрена, клиент может её изменить или отозвать. Он видит состояние и результат рассмотрения с комментарием сотрудника, если тот указан для клиента. Для одобренного отпуска доступны запросы изменения или раннего завершения, а не прямое изменение действующего отпуска.

Перед одобрением сотрудник видит конфликты и выполняет отмену, перенос или замену преподавателя; пока конфликты есть, одобрение недоступно D-444. Клиентский отпуск одобряют сотрудники, сотруднический — супер D-421. Автоматических отпускных продлений/восстановлений нет.

## Рабочее время, закрытия и помещения — D-259–D-264

Преподаватель готовит график с недельными/разовыми перерывами и отправляет суперу. После подтверждения график действует сразу D-435; до этого конфликты разрешены обычными действиями D-444. Сотруднический отпуск одобряет супер, клиентский — сотрудники D-421.

Вне графика и в перерывах запись запрещена всем. До изменения графика конфликтующие встречи отменяют, переносят или меняют преподавателя D-444. Для закрытия школы действует отдельное D-270–D-272: отмена, восстановление и компенсация серии; продление нового абонемента исключено D-428.

Помещения имеют название, необязательный комментарий и архивирование; при записи выбор необязателен, проверяется занятость, дополнительной настройки совместимости нет. По D-275 при архивировании помещение автоматически снимается с будущих занятий и действующих серий с предупреждением о последствиях. Занятия остаются, исторические назначения сохраняются. По D-276 удаление полностью доступно только для никогда не использованного помещения; для использованного — архив. Конкретные макеты прорабатываются в рамках этих ограничений.

## Профиль, безопасность и переключение аккаунтов — D-279–D-283

Текущий профиль объединяет личные данные, экскурсию по интерфейсу, подписку на календарь, рабочие часы/отпуска, пароль, 2FA и активные сеансы. Источник — [ProfilePage.tsx](../MelodyTrack.Web/src/pages/profile/ui/ProfilePage.tsx). Пользователь попросил сохранить нужные возможности и переработать перегруженный интерфейс D-283.

Рабочая компоновка ассистента по D-223: разделы «Личные данные», «График и отпуска», «Безопасность»; подписка на своё расписание остаётся в профиле/клиентском портале по D-287, повтор экскурсии — в справке. На мобильном это короткий список разделов с отдельными экранами. Конкретная компоновка — проектное предложение, а не подтверждение новых функций экскурсии.

В «Безопасности» сначала показываются краткие состояния пароля, аутентификатора, passkey и сеансов с действиями. Формы смены пароля и подключения фактора раскрываются только по действию; одновременно все формы и QR-коды не отображаются. Для passkey — список и явные действия управления. Список сеансов сохраняет текущее устройство, завершение одного и «Выйти везде». Старые кнопки показа/перегенерации резервных кодов не переносятся: восстановление уже выбрано через суперпользователя/сервер D-086. Нельзя отключить обязательную для роли защиту. Точные макеты ещё не созданы.

Регистрация сотрудника — последовательный сценарий по одноразовому приглашению суперпользователя, переданному внешними каналами; сотрудник сам задаёт пароль и настраивает вход с учётом роли. Временного пароля от суперпользователя нет D-279.

По D-280 при запросе второго фактора для переключения прежний аккаунт остаётся активным до успешного подтверждения. Отмена сохраняет прежний аккаунт, успех переключает все вкладки. По D-281 выход завершает доступ выбранного аккаунта в этом браузере, оставляя запись в списке для нового входа; остальные записи не затрагиваются. «Забыть» также удаляет запись и доступно только на экране переключения D-282. В профиле действие «Забыть» не дублируется.

## Уход преподавателя, переносы и календарные подписки — D-284–D-288

В управлении сотрудниками блокировка и архивирование — разные действия. Блокировка сразу прекращает вход, сохраняет занятия/назначения курсов и показывает суперпользователю предупреждение. До архива нужно заменить преподавателя в будущих занятиях/сериях и незавершённых курсах, где он единственный. Исторические данные не переписываются.

При переносе даты/времени создаётся задача уведомить клиента. Для массового переноса серии — одна задача на клиента со списком старых/новых значений за эту операцию. Текст сообщения берётся из настраиваемого шаблона; отправка выполняется сотрудником.

Подписка на своё расписание доступна каждому именно в профиле или клиентском портале D-287. Это уточняет прежнее предложение размещения рядом с расписанием: не добавлять меню подписок на чужих преподавателей из календарного фильтра. Сотрудникам также доступно получение подписки любого клиента; место этой кнопки в рабочем интерфейсе прорабатывается без расширения остальных прав карточки. События содержат время, публичное имя услуги, преподавателя, помещение; предназначенный сотруднику вариант также имя клиента D-288.

## Уведомления, подписки и объявления — D-289–D-294

Повторный перенос обновляет открытую задачу уведомления, сохраняя исходное и последнее актуальное время. Если прежняя задача выполнена, создаётся новая. Массовые переносы остаются сгруппированы по клиенту по D-286; подробности — в [задачах](tasks.md).

Публичное имя услуги необязательно: при отсутствии используется обычное название. Отменённые встречи не входят в актуальную календарную подписку. Блокировка сотрудника отзывает его подписки, архив клиента и замена его ссылки входа — все подписки на клиента. Интерфейс объясняет необходимость получить новую ссылку после отзыва, не обещая удаление ранее скачанных событий из стороннего приложения.

Web Push добровольно включается/выключается для текущего устройства всеми ролями D-293. Push получает только текущий активный аккаунт D-322, не остальные сохранённые. Отказ в разрешении не препятствует работе. По D-323 с уточнением D-326 при действующей сессии системные push могут показываться в фоне и на экране телефона с именем аккаунта и текстом события. Пользователь выбрал подробный показ, а не только общее сообщение. Постоянная открытая вкладка не требуется.

По D-294 управления объявлениями в обычном рабочем интерфейсе нет, в том числе для суперпользователя. Управление доступно только через серверно активируемый «Режим Бога». Это не запрещает показ адресованных объявлений в приложении; прежние аудитории и параметры показа ещё описываются отдельно.

## Исправления и аудит — D-295–D-300

Изменение общей даты проведённой/сгоревшей встречи начинается со снятия действующих результатов её участников. Услуга/длительность неизменны; баланс пересчитывается, льготное использование возвращается D-451. Результаты других встреч не перераспределяются.

Удаление ошибочной встречи доступно без действующих списаний участников, с сохранением истории. Результаты занятий администратор исправляет в календарном месяце даты занятия, супер — без давности. Платежи/расходы администратора имеют отдельную сегодняшнюю границу D-424/D-425; комментарий обязателен в случаях D-424/D-434. Будущее планирование не ограничено месяцем.

Общий аудит доступен только суперу: автор, время, изменение, связи и финансовые последствия, причина необязательная. Основой служит текущий журнал аудита; его сохранение не означает отдельный редактор аудита или расчёт баланса из текста журнала. Конкретный интерфейс остаётся в рамках общего упрощения D-232.

## Услуга и длительность в форме записи — D-306–D-309

При создании услуги длительность выбирается из 30/45/60/90/120 минут, по умолчанию 60. В форме занятия/серии длительность показывается как значение из услуги с вычисленным окончанием; отдельного ручного ввода нет. При редактировании созданной записи услуга отображается без возможности замены, прежняя длительность сохраняется даже после изменения настройки в справочнике. Ошибочный выбор исправляется через разрешённую отмену/удаление и создание новой записи, а не скрытую смену услуги.

В профиле преподавателя нет настройки специализации по услугам; выбор преподавателя не фильтруется по такой связи. График, отпуск и занятость продолжают ограничивать сохранение. Ограничение начала целым часом не запрещает окончание в 13:30/13:45 для коротких услуг.

## Редактирование и завершение серии — D-310–D-313

Дата окончания серии включительна; форма объясняет это рядом с выбором даты. При изменении «это и последующие» выбранная встреча получает новые значения, индивидуальные переносы, замены преподавателя и ручные отмены остальных встреч сохраняются и показываются списком. Услуга и длительность серии остаются прежними D-307–D-308.

Для завершения сотрудник выбирает дату, видит затронутые запланированные встречи и подтверждает отмену начиная с этой даты. Списания нет, история сохраняется. Задача уведомить клиента не создаётся; лишнего переключателя «уведомлять» для этого сценария не требуется. Незавершённые напоминания отменяются по общим правилам. Завершённую серию нельзя возобновить; для продолжения доступно создание новой, без изменения истории старой.

## Горизонт серий и разбор конфликтов — D-383–D-389

При предпросмотре бессрочной серии виден проверенный период: 12 месяцев с дальнейшим регулярным продлением. Для изменения времени, преподавателя и помещения область определяется исходным порядком вхождений; отдельно перенесённая встреча сохраняет исходную принадлежность к части серии.

Поздняя конфликтующая встреча не создаётся, появляется задача и явный экран разбора D-384. Предлагается рабочая страница со списком дат и выбранной проблемой: причина, исходный план, доступные исправления, предпросмотр и сохранение. Доступны предложения переноса, замены преподавателя/помещения, снятия необязательного помещения и явного пропуска. Общий дизайн форм и мобильная адаптация сохраняются. Группировка подтверждена D-387: один открытый разбор/задача на серию со всеми проблемными датами; новые добавляются туда же. Точные макеты ещё разрабатываются.

Действие задачи ведёт к разрешению проблемы; простая отметка выполненной не означает согласованного пропуска. По D-388 исчезновение препятствия показывает готовность к созданию, но требуется подтверждение сотрудника. Клиент видит на своей проблемной дате «Запись требует согласования» D-389, без чужих имён/служебных подробностей и без действий разбора. Предупреждение визуально различается с созданным занятием, не выдаётся за подтверждённую запись и не разрешает отметку результата/списание.

## Кампании и активации — D-314–D-317

Суперпользователь создаёт кампанию на отдельной странице. Длительная форма группирует параметры размера скидки, применимости, срока и условий клиента; перед сохранением явно указано, что созданную кампанию редактировать нельзя. Существующая кампания открывается для просмотра без редактирования. Дополнительный этап публикации или черновик кампании как бизнес-состояние этим не вводятся; локальное сохранение ввода остаётся по общим правилам.

Режим скидки на новую покупку абонемента исключён D-428/D-450. У возвращающегося клиента перерыв проверяется от окончания последнего обычного проведённого/сгоревшего участия по любой услуге D-315.

Супер/администратор активирует код с выбором услуги по D-215; перед подтверждением видны клиент, услуга и предоставляемые условия. Активация не отменяется, отдельной кнопки отмены/удаления нет, включая случай до первого применения. Точная компоновка — работа ассистента в рамках общего упрощения; новые права сотрудникам не добавляются.

### Жизненный цикл кампании и код — D-318–D-321

Суперу доступны отдельные действия остановки новых активаций и удаления никогда не активированной кампании. Остановка сохраняет уже предоставленные права; использованная кампания остаётся в истории. Это не открывает редактирование её настроек. Действие возобновления не согласовано и не включается в интерфейс по умолчанию.

В форме создания поле кода поддерживает ручной ввод и действие «Сгенерировать». Генератор выдаёт уникальные пять букв/цифр; совпадение с кодом сохранённой кампании не позволяет создать дубликат, включая истёкшие кампании. Ограничение ручного ввода длиной пять символов пока не выбрано. Конкретная компоновка и алфавит не требуют отдельной новой подсистемы.

Снятие результата со скидкой на N занятий освобождает использование в рамках той же активации D-451. Отмена/новая активация промокода не создаётся; история сохраняется.

## События уведомлений — D-324–D-325

Клиенту нужны уведомления о назначении курса, новом персональном ДЗ и открытии новых тем. Преподавателю — о новых, перенесённых и отменённых собственных занятиях. Эти события входят в уведомления соответствующего аккаунта и не подменяют задачи ресепшена написать клиенту. Текст и группировка прорабатываются с учётом доступа, тумана закрытых тем и активной сессии; новые права на редактирование не предоставляются.

По D-326 системный push вне приложения показывает имя аккаунта и текст события при действующей сессии текущего аккаунта. Входящие события, показ уведомления и задача сотрудника остаются разными действиями. Получение push не переключает аккаунт; обычные правила входа и доступа сохраняются.

## Правила и действия задач — D-327–D-332

Интервальное правило показывает дату начала как основу последовательности и ближайшие даты. Конец выбирается как бессрочное повторение или дата включительно; поля количества создаваемых задач нет. При повторном включении не предлагаются задачи за время отключения и восстановление отменённых.

Ручная дата откладывания сохраняется при автоматическом пересчёте после переноса урока/смены тайминга шаблона. Сотрудник видит фактический отложенный срок; отмена урока всё равно отменяет незавершённую задачу. В истории доступен возврат выполненной/отменённой задачи в работу администратору/суперу, включая повторяющиеся и системные D-379. Произвольного редактора полей нет.

После полного погашения долга незавершённое напоминание автоматически отменяется с понятной причиной, а не отмечается выполненным обращением. Видимость финансовых подробностей остаётся в пределах согласованных прав.

## Практика и история попыток — D-333–D-338, D-360–D-371

Тренировка автоматически фиксирует фактические длительность без пауз, темп, повторы и контекст. Свободная история есть и у клиентов, и у сотрудников D-364. В ДЗ преподаватель может задать цель по длительности либо количеству повторов; выполнение цели не ставит учебную отметку.

История всех попыток — сворачиваемый блок с пагинацией. Сворачивание не удаляет и не скрывает отдельные факты для другого пользователя. Кнопок удаления попытки и ручного редактирования измеренных результатов нет. Конкретный размер страницы и компоновка прорабатываются ассистентом в рамках общего интерфейса.

Любой пользователь видит свою свободную историю; чужая недоступна даже суперу D-364. Преподаватель читает практику назначенных курсов, без других курсов. Попытки персонального ДЗ видят клиент, преподаватель связанного занятия и супер, включая ДЗ без курса D-365.

У свободной попытки есть одна кнопка применения сохранённой конфигурации к текущему свободному тренажёру с перезаписью настроек D-366. Попытка/измерения не меняются. У сотрудника для доступной попытки есть действие экспорта видео работы тренажёра D-367, без расширения области чтения. Копирование недоступно во время работы тренажёра; интерфейс объясняет, что сначала нужно его остановить D-371. Попытка не завершается автоматически ради применения конфигурации.

Видео заново воспроизводит сохранённую конфигурацию без исполнения пользователя/микрофона D-368. Метроном — самостоятельная отключаемая настройка тренажёра; включённый метроном звучит в видео, экспорт его не переключает D-369. У зацикленной попытки исходная длительность видео — один цикл, можно задать секунды; у незацикленной — сохранённая продолжительность D-370. Подписи и мелкая компоновка прорабатываются ассистентом.

Запуск начинает попытку, пауза сохраняет её текущей; «Стоп» завершает и сохраняет, даже если цель не достигнута. При закрытии/перезагрузке сохраняется прерванная попытка без автопродолжения D-360–D-361. В истории различаются остановленная и прерванная попытки, без автоматической учебной оценки. После изменения упражнения прежние попытки показывают параметры на момент выполнения D-363.

Локально для аккаунта и тренажёра запоминаются настройки свободного режима, без синхронизации между устройствами. Настройки не подменяют историю и не меняют параметры выданного ДЗ.

Встроенный тренажёр учебного материала имеет фиксированные автором настройки и учебную историю аналогично ДЗ D-377. Свободная настройка остаётся отдельным режимом.

Фактический возврат денег клиенту D-378 — отдельное финансовое действие с собственным исходным фактом. Его нельзя обозначать тем же действием, что отмену ошибочного платежа/покупки; подробная форма ещё проектируется.
