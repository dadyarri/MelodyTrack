# Работа над спецификацией MelodyTrack v2

Эта папка описывает новую версию продукта. Корневые инструкции по работе с репозиторием сохраняют силу. Пользователь явно разрешил заново проектировать продукт; архитектура старой реализации служит материалом для анализа.

- Пишите спецификацию на русском языке, используя устойчивые термины и идентификаторы требований.
- Различайте подтверждённые требования, предложения, открытые вопросы и сведения о текущей реализации.
- Ответ пользователя фиксируйте в журнале решений и связанных разделах. Не выдавайте предложение или отсутствие ответа за принятое решение.
- По D-224 вопросы об интерфейсе задавайте более крупными связанными пачками с разумными предложениями по умолчанию. Согласовывайте существенные решения, а мелкую компоновку прорабатывайте самостоятельно в рамках D-223; не превращайте обсуждение в цепочку одиночных подтверждений.
- По D-391 пользователь передал реализацию бэкенда ассистенту: пишите небольшими законченными порциями и останавливайтесь после каждого шага для ручного ревью пользователем. Это изменяет прежнее распределение D-135/D-223, но сохраняет согласование предметных правил до реализации. Фронтенд также проектирует и реализует ассистент по требованиям и согласованному дизайну.
- Сохраняйте происхождение требований: сообщение пользователя, раздел roadmap или конкретный документ/код старой версии.
- Описывайте наблюдаемое поведение, ограничения, состояния, ошибки и критерии приёмки до выбора технической реализации.
- Детализируйте будущие возможности по мере определённости требований; не создавайте инфраструктуру под неподтверждённые сценарии.
- Не переносите дефекты и противоречия старой версии как обязательные правила. Не объявляйте существующее поведение ошибкой без указания основания.
- По D-232 большинство текущих сценариев устраивает заказчика. Используйте их как отправную точку; не перепроектируйте каждый экран лишь из-за переписывания. По D-225 сохраняется приблизительно текущая палитра, по D-231 желательное восстановление ввода требует упрощения, а не автоматического переноса инфраструктуры черновиков.
- Исходный код и исторический roadmap пока сохраняются. Изменение спецификации само по себе не разрешает менять поведение текущего приложения.
- Не запускайте сборки, тесты, генерацию клиента, форматтеры и другие проверочные конвейеры без отдельного разрешения пользователя.
