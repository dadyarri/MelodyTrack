# Задачи, шаблоны и календарные правила

**Актуальная граница — D-446:** вся механика курсов и домашних заданий отложена, включая персональное ДЗ без курса, отметки выполнения, учебные уведомления и напоминания о ДЗ. Прежние согласованные учебные правила ниже сохранены для будущего возвращения, а не текущей реализации. Исторические данные при переносе сохраняются. Вопросы собраны в отдельной категории [реестра](../rewrite/docs/open-questions.md). Обычные задачи и результаты/списания занятий остаются в текущем объёме; отсрочка относится к учебной механике.

## Уточнения по ответам заказчика — 04.11.2026

- D-429: прошедшее занятие без результата создаёт задачу; тайминг, дедупликация, группировка и закрытие после отметки ещё согласуются.
- D-437: задачу можно вернуть всегда. При конфликтующем/исчезнувшем основании она становится проблемной с описанием конфликта; отказ вместо возврата не является выбранным поведением. Нельзя молча отменять следующую задачу или скрывать неактуальность основания.
- D-438: возле задач нужен индикатор с числом. Что он считает и как связан с прочтением уведомлений, ещё не выбрано.
- BIZ-25: правила повторов долга, группировки отмен и повторного обращения об изменённом ДЗ остаются открытыми.

Рабочие правила ниже приведены к актуальным решениям. История заменённых требований хранится в журнале; учебные и иные явно отложенные разделы не означают текущую реализацию. Источник — [ответы пользователя](../rewrite/docs/open-questions.md) и [журнал решений](decisions.md).

Статус: подтверждены редактор, календарные повторения без накопления, общая очередь, права, выбор применения изменений, опорная дата интервала, окончание/повторное включение правил и приоритет ручного откладывания. Любой тип задачи можно вернуть в работу; после погашения долга напоминание отменяется. Оставшиеся поля, отдельные системные переходы и техническая модель ещё детализируются.

Связанные документы: [каталог](capabilities.md), [права](access.md), [расписание](scheduling.md), [дизайн-гайд](design-guide.md), [решения](decisions.md).

Для уведомления о переносе D-286 используется настраиваемый шаблон сообщения. Массовый перенос в одной операции создаёт одну задачу на клиента со списком изменений. По D-289 последующий перенос при открытой задаче обновляет её, а не создаёт дубликат: исходное время до первого ещё не сообщённого переноса сохраняется, новое заменяется актуальным. Например, при переносах 18:00 → 19:00 → 20:00 до выполнения задачи сообщение показывает 18:00 → 20:00. После выполнения следующий перенос создаёт новую задачу; выполненная история не меняется. Это системное обновление, не разрешение произвольного редактора задачи. Поведение отменённой/отложенной задачи при новом переносе и обновление частично пересекающихся списков массовых переносов ещё детализируются.

Создание новых пользовательских шаблонов ограничено календарными задачами. Тайминги и шаблоны сообщений существующих системных задач школы, зависящих от событий, настраиваются по D-163; состав полей и интерфейс ещё детализируются. Произвольный конструктор новых событий и условий пользователь не запросил.

Набор повторений задач шире набора повторений занятий. Ограничение занятий выбранными днями каждой недели D-021 не распространяется на T-004.

При завершении серии с выбранной даты D-312 новая задача уведомить клиента не создаётся. Это исключение не отключает задачи о переносе встречи/серии и отменах из-за отпуска или закрытия школы. Незавершённые напоминания по отменённым встречам отменяются по общим правилам, выполненная история сохраняется.

По D-417 обязательны генерация/обработка, настройки и история прежних неучебных задач, а не только чтение перенесённых строк. Напоминания о ДЗ и их прежние переходы отложены D-446. Неполное покрытие текущими моделями описано в M-08 карты переноса.

## Словарь и разделение действий

Рабочая модель для согласования; она не требует отдельных таблиц или сервисов для каждого термина.

| Понятие | Назначение | Пример |
| --- | --- | --- |
| Шаблон задачи | Название, содержание, возможный текст сообщения и доступные подстановки | «Напомнить об уроке» с именем и временем |
| Правило создания | Объясняет, когда и для кого появляется задача | За согласованное время до занятия либо каждую пятницу |
| Календарное повторение | Даты и время появления задач по пользовательскому календарному правилу | Проверить расходники каждую пятницу в 17:00 |
| Отдельная задача | Конкретное действие сотрудника со сроком, состоянием и связанными данными | Проверить расходники в ближайшую пятницу |
| Повторное напоминание | Повтор обращения по сохраняющемуся условию | Повторно связаться по долгу; точная политика открыта |
| Откладывание задачи | Изменение срока уже существующей задачи | Перенести действие с сегодняшнего дня на завтра |

Текст сообщения клиенту и получатель сообщения — разные сведения. Задачи выполняются через общую очередь ресепшена без назначения конкретному сотруднику (D-043). Адресат сообщения не является назначенным исполнителем. Внутренняя задача школы, например проверка расходников, может не требовать сообщения клиенту; это предложение к составу формы.

Период создания новых задач, откладывание одной задачи и повторное напоминание должны иметь понятные названия и объяснение последствий. Настройки нельзя обозначать одним неоднозначным полем «повтор» без описания смысла.

## Предлагаемый интерфейс

По D-237 подтверждён обычный рабочий список с разделами актуальных, отложенных и истории; быстрые действия — выполнить, отложить, отменить, подробности по необходимости. Управление общими шаблонами отдельно у суперпользователя. Остальные детали этого раздела — предложения для макетов; конкретная компоновка и поля ещё не утверждены.

### Рабочий список задач

- Отдельная задача в общей очереди показывает действие, срок, источник и состояние. Связь с клиентом, занятием или преподавателем показывается, если она есть; выбор исполнителя не нужен по D-043.
- Доступны поиск и фильтры по сроку, состоянию и источнику; состав фильтров уточняется на сценариях ресепшена.
- По D-237, D-241 из карточки доступны выполнить, отменить и отложить; отдельной формы произвольного редактирования названия, описания, срока и подготовленного текста нет.
- Действие над одной задачей не должно незаметно менять общий шаблон. Отложить задачу — самостоятельное разрешённое действие, не редактор всех полей.
- Текст для клиента можно просмотреть перед контактом и скопировать; произвольная правка подготовленного текста внутри отдельной задачи не разрешена D-241.

Контакты клиента в v2 многозначные. Для обращения по конкретному виду используется его основной контакт D-116. Это не выбирает автоматически вид/канал сообщения и не утверждает автоматическую отправку: правило выбора канала и момент получения актуальных контактных данных ещё описываются. Архивирование вида сохраняет существующие контакты D-117; совпадение номера/email не объединяет задачи разных клиентов D-118.

По D-240 администратор может создать разовую задачу в общей очереди без шаблона и повторения; это не даёт прав управления шаблонами. После создания применяются общие действия над задачей, а не произвольный редактор полей D-241. Исправление завершённой задачи и точная форма создания ещё описываются. Персональное назначение исключено D-043.

### Задача разбора конфликта расписания — D-384

Источник — конфликт вхождения при продлении 12-месячного окна серии, не созданное скрытое занятие. Из задачи сотрудник переходит в [разбор](scheduling.md) с причинами, предпросмотром исправления и явным пропуском. Закрытие карточки задачи само по себе не решает дату и не создаёт встречу. По D-387 есть одна открытая задача на серию, содержащая все проблемные даты; новые пополняют этот разбор. По D-388 исчезновение причины не создаёт занятие автоматически: требуется подтверждение сотрудника. Общая очередь и права админа/супера сохраняются.

### Управление шаблонами и правилами

Управление доступно только суперпользователю по T-005. Предлагаются список с понятным описанием действия и времени, поиск, состояние включения и переход в редактор.

Редактор содержит смысловые блоки:

1. **Что сделать:** название и содержание задачи; при необходимости текст сообщения клиенту.
2. **Когда:** разовая дата или календарное повторение для нового пользовательского шаблона. Для существующего системного правила — только применимые к нему настройки.
3. **Связанные данные:** клиент или другое доступное основание, если оно требуется; правила выбора ещё открыты.
4. **Предпросмотр:** пример итогового текста и ближайшие даты, на которые появятся задачи.
5. **Последствия сохранения:** выбор «только новые» или «также открытые и отложенные» по D-039 с сохранением индивидуальных правок. При выключении предлагается также отменить существующие задачи по D-040.

Временной сдвиг перед занятием предлагается показывать как «за 3 дня до начала», а не как неочевидное числовое смещение. Для ДЗ стандартное значение — 72 часа, редактируемое по D-162–D-163; форма показывает применённый интервал и его предпросмотр.

Подстановки предлагается вставлять через подписанные элементы («имя клиента», «дата занятия»), показывать их значение в предпросмотре и объяснять отсутствие необходимых данных. Набор подстановок зависит от типа правила. Использование выражений и программного кода в редакторе не требуется подтверждёнными сценариями.

### Создание календарного правила

Предлагаемый сценарий:

1. Суперпользователь выбирает создание календарной задачи.
2. Задаёт название, содержание и разовый срок либо календарное повторение.
3. Для повторения выбирает подтверждённый вариант T-004 и его параметры.
4. Видит описание словами, ближайшие даты и пример отдельной задачи.
5. Сохраняет правило; в рабочем списке появляются задачи по выбранной политике формирования.

Ежедневно, по дням недели, по числу месяца и каждые N дней/недель — подтверждённые варианты. Отсутствующее число заменяется последним днём месяца (D-042): например, ежемесячное 31-е в апреле приходится на 30-е, а в мае снова на 31-е. Исходное число в правиле не меняется из-за короткого месяца.

По D-141 календарные правила используют единый Europe/Moscow, абсолютные моменты хранятся и передаются в UTC D-133. Интервал N дней/недель считается от заданной даты начала D-327: каждые три дня с 1-го — 1, 4, 7, 10-го. Позднее выполнение не сдвигает последовательность; выбирается ближайшая будущая дата. Повторение бессрочно либо до даты включительно D-328, лимит количества задач не вводится. Детали поля времени, нескольких времён за день и пропуска выходных ещё описываются, не наследуются автоматически от занятий.

На телефоне предлагается отдельный экран редактирования с доступным сохранением, прокруткой и клавиатурой. Редактор должен обслуживать подтверждённые iPhone 13 и iPhone 13 mini; конкретный макет создаётся позднее.

## Напоминание о ДЗ перед уроком

Подтверждено U-005, D-161–D-163: нужна задача напомнить клиенту о ДЗ перед уроком; отсутствие выбранной темы курса не препятствует её созданию. Речь о задаче сотрудникам в общей очереди, а не о самостоятельно отправленном системой сообщении клиенту. Все тайминги и шаблоны сообщений настраиваются суперпользователем.

Подтверждённое поведение по умолчанию D-162:

1. Интервал составляет 72 часа до начала урока; это начальное значение настройки, а не константа предметной логики.
2. Если будущий урок создан позже рассчитанного по настройке срока, задача появляется сразу.
3. При переносе урока срок незавершённой задачи пересчитывается; при отмене урока незавершённая задача отменяется.

И поздняя запись, и пересчёт при переносе используют интервал, применённый к конкретной задаче, с учётом выбранной области правок шаблона D-039. Нельзя изменить интервал в редакторе, но оставить в другом обработчике жёсткие 72 часа. Сохраняются правила индивидуальных правок; детали их сочетания с переносом урока и поведение завершённых задач ещё описываются.

## Изменения и жизненный цикл

### Изменение шаблона — D-039

При сохранении нового текста или параметров суперпользователю предлагается выбрать:

1. Применить изменения только к новым задачам; существующие сохраняют прежние параметры.
2. Применить также к открытым и отложенным задачам этого шаблона, сохранив индивидуальные правки.

Уточнение D-241: ручного редактора полей отдельной задачи нет. Сохранение индивидуальных изменений относится к разрешённому откладыванию: по D-330 выбранная сотрудником дата сохраняется при переносе урока и применении нового тайминга шаблона к существующим задачам. При этом актуальные данные/текст могут обновляться в выбранной области D-039. Отмена урока всё равно отменяет незавершённую задачу. Универсальная подсистема правок каждого поля не требуется.

По D-379/D-437 администратор и супер возвращают любой тип выполненной/отменённой задачи. Если следующая задача уже открыта или основание исчезло, возвращённая задача сохраняется проблемной с описанием конфликта. История переходов сохраняется; право возврата не зависит от актуальности основания.

### Выключение шаблона или правила — D-040

При выключении предлагается также отменить уже открытые и отложенные задачи этого шаблона/правила. Пользователь решает, выполнить эту отмену или оставить существующие задачи. Новые задачи по выключенному правилу не создаются.

Пример: правило «проверять расходники по пятницам» выключается. Суперпользователь может подтвердить отмену оставшихся задач этого правила либо оставить их для выполнения.

По D-329 повторное включение продолжает правило с ближайшей будущей даты по его календарю, без задач за время выключения и без восстановления отменённых. Если при выключении открытую/отложенную задачу оставили, она сохраняется и препятствует созданию новой по D-041.

### Невыполненная календарная задача — D-041

Если задача по календарному правилу уже открыта или отложена, следующие даты этого правила не создают новые копии. После выполнения или отмены отдельной задачи повторение продолжается по ближайшей будущей дате (D-044–D-045). Это единая выбранная политика; отдельный переключатель режима накопления для каждого правила не нужен.

Пример: задача «проверить расходники» появилась в пятницу и не выполнена. В следующую пятницу в очереди остаётся одна невыполненная задача этого правила, а не две.

Это правило относится к календарным повторениям. Оно не объединяет напоминания разным клиентам и не отменяет задачу уведомления по отдельному событию школы.

После позднего выполнения задачи пропущенные даты не порождают догоняющие задачи. Пример: пятничную задачу выполнили во вторник, пропустив ещё одну пятницу; следующая задача относится к ближайшей будущей пятнице. Отмена одной задачи действует аналогично для выбора следующей даты, но сохраняется отдельным состоянием истории; общее правило остаётся включённым.

Опорная дата и повторное включение определены D-327/D-329. Ещё требуется уточнить срок текущей невыполненной задачи при пропущенном повторе и критерий просрочки. Выбор ближайшей будущей даты не определяет технический способ предварительного создания строк в БД.

### Остальные нерешённые правила

Требуется выбрать правила:

- Оставшиеся случаи сочетания обновлений источника и шаблона; ручная дата откладывания сохраняется D-330, произвольного редактора полей нет D-241.
- Возврат любого типа уже разрешён D-437; конфликт сохраняется проблемным, без отмены следующей задачи. Ограничение D-041 относится к автоматической генерации копий и не запрещает ручной возврат истории. Проблемная возвращённая задача может сосуществовать с открытой следующей; пока есть незавершённые задачи правила, генератор не добавляет новые. Возвращённая проблемная задача с исчезнувшим основанием не отменяется немедленно тем же автоматическим правилом неактуальности: конфликт должен оставаться видимым до решения сотрудника.
- Техническое представление окончания повторения по дате или бессрочности D-328 с сохранением выполненной истории.
- Поведение напоминания при изменении ДЗ и частично пересекающихся массовых переносах; перенос/отмена урока определены D-162/D-330, полное погашение долга — D-332.
- Как исключить повторную постановку уже выполненной задачи по тому же основанию?
- Когда задача считается просроченной и сохраняется ли её первоначальный срок при пропущенных повторах? Догоняющие задачи после позднего выполнения не создаются по D-044.
- Как обрабатывать одновременно редактируемые правило и отдельную задачу?

Предложение к упрощению: календарные правила настраиваются параметрами дат и времени; системные задачи используют ограниченный перечень правил школы. Не требуется универсальная среда автоматизации для произвольных действий. Общие понятия задачи и её состояния могут применяться к обоим источникам; устройство БД и реализации ещё не выбрано.

### Исчезновение долга — D-332

После полного погашения долга незавершённое напоминание о нём отменяется автоматически как утратившее актуальность. Оно не становится выполненным обращением к клиенту; история и причина автоматического действия сохраняются. Ручное откладывание не сохраняет неактуальную задачу. Сам долг определяется исходными финансовыми данными и вычисляемым балансом, не отдельным вручную переключаемым флагом. Права на финансовые сведения и исправления Q-025/Q-190 остаются у заказчика. Повторное возникновение долга и правила последующих напоминаний ещё детализируются.

## Техническая обработка 31.10.2026 — D-400–D-402

Незавершённые задачи и другие выразимые инварианты защищаются ограничениями/индексами БД плюс адресными блокировками. Изменение предметного состояния, аудит и последующая работа фиксируются одной транзакцией; обработка повторяема по постоянному ключу. Небольшой набор периодических обработчиков Quartz работает порциями с сохранённой позицией. Это не разрешение накопления календарных копий или догоняющих задач; отдельная шина не выбрана. Конкретные частоты/порции/повторы и открытые случаи возврата задачи ещё детализируются.

## Задача о забытом результате

Для прошедшей встречи без результата создаётся задача D-429. При парной встрече забытый результат определяется по участникам. Тайминг, группировка и закрытие после отметки остаются BIZ-38, не считаются утверждёнными технической дедупликацией. Задача не создаёт списание.
